# Text field

Reference: Minimal UI kit "Text field" page, sections Outlined, Filled, Standard (each: General,
With adornments, With helper text, Type, Sizes, Select, Multiline; content only). Upstream: MUI
`TextField`, `InputAdornment` (ADR-0015). Created with `/component`.
Reference URL: https://minimals.cc/components/mui/text-field

## Purpose
Enter and edit text: a native `<input>`, `<textarea>` or `<select>` with a floating label, optional
adornments and helper text.

## Anatomy
```
div[data-ok-text-field][data-ok-variant][data-ok-size][data-ok-margin][data-ok-error]?[data-ok-full-width]?[data-ok-shrink]?[data-ok-hidden-label]?[data-ok-focused]?[data-ok-notched]?[data-ok-disable-underline]?[data-ok-min-rows]?[data-ok-max-rows]?[data-ok-input-base]?
  label[data-ok-text-field-label][for=<input id>]? (› span[data-ok-text-field-asterisk][aria-hidden] " *")
  div[data-ok-text-field-control]
    span[data-ok-text-field-adornment="start"][data-ok-disable-pointer-events]?   (optional; any element)
    input[data-ok-text-field-input][id][placeholder]   | textarea[…][rows][placeholder] | select[…] › option
    svg[data-ok-text-field-select-icon][aria-hidden]?  (select)
    span[data-ok-text-field-adornment="end"]?
    fieldset[data-ok-text-field-outline][aria-hidden] › legend? › span (label + " *")   (outlined only)
  div[data-ok-text-field-helper][id]?                  (linked by aria-describedby)
```
Standalone inputs (4.18.26: `InputBase`, `OutlinedInput`, `FilledInput`, `Input`) are this markup
without the label and the helper, with `data-ok-input-base` on the root; `InputBase` has no
`data-ok-variant` (no outline, fill or underline; input padding 4px 0, small 1px 0). Their notch
stays closed unless `data-ok-notched` (OutlinedInput `label` fills the legend only).
Inputs and textareas always carry a `placeholder` (" " when none): `:not(:placeholder-shown)` is
how CSS knows there is a value. React renders `data-ok-runtime="off"` on the root; `ref` and the
remaining props go to the input; `className` / `style` to the root.

React: `label`, `helperText`, `startAdornment` / `endAdornment` (`InputAdornment position`),
`multiline` + `rows`, `select` + `<option>` children, `value` / `defaultValue` /
`onChange(value)`, `id` (default `useId()`), native input props. Renamed: `slotProps.input.*Adornment`
→ `startAdornment` / `endAdornment`, `slotProps.inputLabel.shrink` → `shrink` (no slotProps).
`color` keeps MUI's name and values plus `default` (the text color, as on the reference), which is
the default (MUI: `primary`): lines use the palette's `main`, the focused label its AA `-text` tone.
Listbox `select`: `selectProps={{ native: false, … }}` (MUI `SelectProps` / `slotProps.select`)
with `MenuItem` children composes the Select (select.md) in the control: the control gets
`data-ok-select` (+ `data-ok-auto-width` / `data-ok-display-empty`), the trigger
`div[data-ok-text-field-input][data-ok-select-display][role=combobox]` replaces the `<select>`,
followed by the hidden `input[data-ok-select-input]`, the icon (`data-ok-text-field-select-icon
data-ok-select-icon`), the outline and the Select's popover; the label gets `id` (`<id>-label`).
`select` alone stays native (MUI's default is the listbox; additive, no DOM change).
`notched`, `disableUnderline` and `inputComponent` (4.18.26) work on TextField too (MUI
`slotProps.input.*`). Single
values only (`value` stays a string): use FormControl + Select for `multiple`. Not applicable:
`sx`, `classes`, `slots`, `slotProps`.

## Layout and tokens
- Text `--ok-font-size-lg` (15px) / 24px; label rest `--ok-text-secondary` 15px (filled:
  `grey-700` in light schemes, AA on the tint), floated 16px × 0.75 semibold; focus
  `--ok-text-primary` (or `--ok-c-text` with `color`); error `--ok-palette-error-text`; disabled
  `--ok-text-disabled`. Transitions `--ok-duration-shorter` `--ok-easing-decelerate`.
- Outlined: border 1px grey-500 at 0.2 → hover text-primary → focus 2px; radius `--ok-radius-md`;
  input padding 16 / 14px (small 8 / 14px) → 56 / 40px; label 14px in, rest y 16 (small 8), up −9.
- Filled: grey-500 tint 0.08 (hover / focus 0.16, disabled 0.24, error error channel 0.08);
  padding 24 12 8 (small 20 12 4; no label 16 12 / 8 12); label x 12, up 6 (small 4); focus adds
  a 2px inset ring (the reference has none).
- Standard: underline 1px grey-500 at 0.32 → hover 2px → focus 2px line growing from the
  middle; label space 16px above; padding 4px 0 (small 2px 0).
- Adornments: `--ok-text-secondary`, 14px semibold, 8px from the input. Helper: caption 12 / 18px,
  margin 6px 12px 0, `--ok-text-secondary` (also when disabled, for AA).
- Select: native, `appearance: none`, own arrow 20px at 7px from the end.
- Multiline: textarea `resize: none`; with min / max rows it grows (`field-sizing: content`,
  `min-height` / `max-height` = rows × 1lh); fallback: `rows` = minRows, scrolls.

## Responsive behavior
Inline-flex column; `fullWidth` stretches. No breakpoint rules; the label truncates with an
ellipsis, helper text wraps.

## States
`:focus-within`, input `:disabled`, `:placeholder-shown`, `[data-ok-error]`, hover.

## Behavior
CSS only. HTML runtime `text-field`: `data-ok-min-rows` / `data-ok-max-rows` → `--_ok-min-rows` /
`--_ok-max-rows` (CSSOM, observed); `data-ok-error` → the input's `aria-invalid="true"` (removed
again only if the runtime set it); a `button[data-ok-text-field-reveal]` inside the field toggles
the input between `password` and `text` and sets `aria-pressed` (React apps keep `type` in state).

## Keyboard
Native input, textarea and select behavior.

## Accessibility
`<label for>` names the input (no label → `aria-label`); helper via `aria-describedby`; error
sets `aria-invalid`; the asterisk is `aria-hidden` (the input is `required`). The resting label is
`text-secondary`, not the reference's `text-disabled` (AA).

## Events / API
HTML: native `input` / `change`. React: `onChange(value)`.

## Copy to clipboard (roadmap 4.20)
Reference: Minimals "Utilities" page (https://minimals.cc/components/extra/utilities), section
"Copy to clipboard": a field with a copy button in its end adornment ("onChange"), a paragraph
copied on double click ("onDoubleClick"), each copy followed by a "Copied!" toast. Upstream: the
reference's `useCopyToClipboard` hook (`{ copy, copiedText }`, usehooks-ts).

- **Core** `copyToClipboard(text, { document? }): Promise<CopyResult>` (`core/src/clipboard`):
  never throws. Outside a user gesture (`navigator.userActivation.isActive === false`, checked
  before any await) → `{ ok: false, reason: "gesture" }` without calling the browser. Clipboard API
  `writeText`; no API → the copy command (`execCommand("copy")` with a one-off `copy` listener
  that writes the text: no text area, focus and selection untouched) or `"unsupported"`; the API
  rejects (permission, policy) → the copy command, else `"denied"`. `clipboardText(element)`:
  form control value, else text with white space collapsed.
- **React** `useCopyToClipboard()` → `{ copy(text): Promise<CopyResult>, copiedText }`
  (`copiedText` = last successful copy, `null` after a failure). Apps compose an `IconButton` in an
  `InputAdornment` and call `toast.success` / `toast.error` with the result.
- **HTML** runtime `clipboard` (behavior-only folder, markup in `text-field/examples`): triggers
  `[data-ok-clipboard-copy]` (value = source id; empty = the text field's input around a button,
  else the trigger itself), `data-ok-clipboard-text` (literal text), `data-ok-clipboard-trigger=
  "dblclick"`, `data-ok-clipboard-toast` / `data-ok-clipboard-error-toast` (`<template>` toasts shown
  in the page's toaster, or `data-ok-toast-toaster`). Event `ok:clipboard:copy` (`detail.text`,
  `ok`, `reason?`), instance `copy()`. React markup (`data-ok-runtime="off"`) is never handled.
- **Announcement:** the toast. The toaster list is a polite live region, so "Copied!" (or the
  error) is announced; the docs tell apps without a toaster to announce the result themselves.
- **Double click** is a pointer-only shortcut: the story adds a "Copy text" button that copies the
  same paragraph (WCAG 2.1.1), an intentional addition to the reference.
- Not built: copying rich text / images (`ClipboardItem`), reading the clipboard (paste).

## Parity notes
React stories render the password button without state (apps own `type`, see the docs page);
`data-ok-text-field-reveal` is an HTML hook (ignored by parity), and so are the
`data-ok-clipboard-*` triggers (React copies from click handlers).
