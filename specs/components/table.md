# Table

Reference: Minimal "Table" page (sections Basic, Sorting & selecting, Grouping & fixed header,
Collapsible, Pagination with API). Upstream: MUI `Table`, `TableHead` / `TableBody` / `TableFooter`, `TableRow`,
`TableCell`, `TableContainer`, `TableSortLabel`, `TablePagination` (ADR-0015).
Reference URL: https://minimals.cc/components/mui/table

## Purpose
Native `<table>` markup with the Minimal look, plus the interactive parts tables need: sortable
headers, row selection, collapsible detail rows and pagination. React leaves data to the app (like
MUI); the HTML runtime sorts, selects and pages the rows already in the DOM.

## Anatomy
```
section[data-ok-table-container]                          holds the table (overflow: visible with a Scrollbar)
  section[data-ok-scrollbar][aria-label][tabindex=0]       scrolls — the Scrollbar component (set a max-height for a sticky header)
    table[data-ok-table][data-ok-size][data-ok-padding][data-ok-sticky-header]?[id]   React: + data-ok-runtime="off"
      thead › tr › th[scope=col][aria-sort]?[data-ok-align]?[data-ok-padding]?
        button[type=button][data-ok-table-sort-label][data-ok-direction][data-ok-active]?[data-ok-hide-sort-icon]?
          … label, span[data-ok-table-sort-icon][aria-hidden=true] › svg (arrow down; rotated when ascending)
        input[type=checkbox][data-ok-table-select-all][aria-label]          selection column (native checkbox)
      tbody
        tr[data-ok-hover]?[data-ok-selected]?
          td | th[scope=row] [data-ok-align]?[data-ok-padding]?[data-ok-size]?
          input[type=checkbox][data-ok-table-select][aria-label]            in a selection cell
          button[data-ok-icon-button][data-ok-table-expand=<detail id>][aria-expanded][aria-controls][aria-label]
        tr[data-ok-table-detail][id][hidden]? › td[colspan]                 detail row of the row above
      tfoot? › tr › td
div[data-ok-table-pagination=<table id>]                                   React: value "" + data-ok-runtime="off"
  label[data-ok-table-pagination-rows] › "Rows per page:" select          (only with 2+ options)
  span[data-ok-table-pagination-displayed][aria-live=polite] "1–5 of 12"
  div[data-ok-table-pagination-actions] › button[data-ok-icon-button][data-ok-table-pagination-action=first|previous|next|last][aria-label][title][disabled]?
```
Sort labels go in the last header row (one header cell per column). Detail rows follow the row
they belong to; sorting and paging move and hide them together with it.

Cell overrides (`TableCell` props ↔ attributes, absent = inherit the table's): `align`
(`left` `center` `right` `justify`; numbers are right-aligned) → `data-ok-align`, `padding` →
`data-ok-padding`, `size` → `data-ok-size`, `sortDirection` (`asc` `desc` `false`) → `aria-sort`,
`scope`. Row: `hover` → `data-ok-hover`, `selected` → `data-ok-selected`.

Pagination (`TablePagination` ↔ HTML): `count` (`-1` = unknown) ↔ number of row groups or
`data-ok-count`; `page` (0-based) ↔ `data-ok-page`; `rowsPerPage` ↔ the selected `<option>`;
`rowsPerPageOptions` (default `[10, 25, 50, 100]`, `-1` = all) ↔ the `<option>`s;
`onPageChange(page)` / `onRowsPerPageChange(rowsPerPage)` ↔ `ok:table-pagination:change`;
`labelRowsPerPage`, `labelDisplayedRows({ from, to, count, page })`, `getItemAriaLabel(type)`,
`showFirstButton`, `showLastButton`, `disabled` ↔ markup.

## Layout and tokens
- Cells: body2, `--ok-text-primary`, padding 16px (`small`: 6px / 16px), bottom border `1px dashed
  --ok-divider`; `checkbox` padding: 48px wide, 8px start; `none`: 0.
- Header: `--ok-bg-neutral` band, `--ok-text-secondary`, weight 600, 24px line (56px row); sticky:
  `--ok-bg-paper`, z-index 2, a second header row sticks below the first.
- Footer: caption, secondary text.
- Rows: hover `--ok-action-hover` (hover-capable devices); selected primary channel 8 % (12 % hovered).
- Sort label: arrow 18px, hidden when inactive (50 % on hover / focus), shown when active; text
  primary when active or hovered. `hideSortIcon`: no arrow while inactive.
- Detail row: `--ok-bg-neutral`; the expand button's chevron turns 180° when open.
- Pagination: flex, wraps, right-aligned, 16px gaps, min-height 64px; prev/next are small icon
  buttons; the rows-per-page `<select>` is native (Select component pending).

## Behavior
- React: data is the app's (sort, select, page in state; `compareCellValues`, `nextSortDirection`,
  `pageRange`, `selectAllState` from `@owlky/core` help). `TableExpandButton` / `TableDetailRow`
  take `expanded` / `open` from the app.
- HTML runtime (`table`, `table-pagination`):
  - sort label click → cancelable `ok:table:sort` `{ column, direction }` → rows (with their detail
    rows) reordered by `data-ok-sort-value` or the cell text (numbers numerically), `aria-sort` and
    the labels updated, pagination refreshed;
  - row checkbox → `data-ok-selected` on its row, the select-all checkbox updated (checked /
    indeterminate); select-all → every row (all pages); then `ok:table:select` `{ rows }`;
  - expand button → cancelable `ok:table:expand` `{ row, expanded }` → `hidden` and `aria-expanded`;
  - pagination → cancelable `ok:table-pagination:change` `{ page, rowsPerPage }` → rows outside the
    page get `hidden`, the label and buttons are updated. With `data-ok-count` (server-side) rows
    aren't touched: the app replaces them.
- With `Pagination` (story "Pagination with API"): React slices the rows for `page`; in HTML
  `nav[data-ok-pagination="<table id>"][data-ok-rows-per-page]` pages the rows the same way (see
  specs/components/pagination.md). Sorting refreshes either kind of pagination.

## Keyboard
Sort labels, checkboxes, expand and page buttons are native buttons / inputs (Tab, Enter / Space).
The Scrollbar inside the container is the focusable scroll region (arrow keys scroll it).

## Accessibility
- `aria-sort` on the sorted header cell; checkboxes and icon buttons need names (`aria-label`).
- Name the Scrollbar (`aria-label`): it is the focusable region; the container stays unnamed and
  unfocusable. Without a Scrollbar, name the container instead: it scrolls natively (as before).
- The displayed-rows label is `aria-live="polite"`.
- Header text (`--ok-text-secondary` on `--ok-bg-neutral`) meets AA in both schemes.

## Events / API
`ok:table:sort` (cancelable), `ok:table:select`, `ok:table:expand` (cancelable),
`ok:table-pagination:change` (cancelable). Instances: table `sort(column, direction?)`,
`expand(row, open?)`; pagination `page`, `rowsPerPage`, `setPage(page)`,
`setRowsPerPage(rows)`, `refresh()`.

## Responsive
Mobile first: the container scrolls horizontally when the table is wider than the screen (the page
never overflows); pagination wraps onto two lines below ~420px. No breakpoint changes otherwise.
