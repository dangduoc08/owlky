# Stepper

Reference: Minimal UI kit "Stepper" page, sections Horizontal linear stepper, Linear alternative
label, Vertical linear stepper, Customized stepper, Mobile stepper (content only). Upstream: MUI
`Stepper`, `Step`, `StepLabel`, `StepConnector`, `StepContent`, `MobileStepper` (ADR-0015).
Created with `/component`.
Reference URL: https://minimals.cc/components/mui/stepper

## Purpose
Progress through numbered steps (wizard, checkout). Presentational: the app owns the active step.
CSS for the look; core `stepState` derives each step's state (React and the HTML runtime
`stepper`); `mobile-stepper` keeps the compact bar in step.

## Anatomy
```
ol[data-ok-stepper][data-ok-orientation][data-ok-variant][data-ok-alternative-label]?[data-ok-active-step][aria-label]
  li[data-ok-step][data-ok-active | data-ok-completed | data-ok-disabled][aria-current="step"]?
    div[data-ok-step-connector][aria-hidden="true"] › span[data-ok-step-connector-line]   (index > 0)
    span[data-ok-step-label][data-ok-error]?
      span[data-ok-step-icon][data-ok-custom]?[aria-hidden="true"]
        span[data-ok-step-icon-text] svg[data-ok-step-icon-check] svg[data-ok-step-icon-error]
        (custom: the icon node)
      span[data-ok-step-label-text]
        span[data-ok-step-label-title] span[data-ok-step-label-optional]?
    div[data-ok-collapse][data-ok-timeout="auto"][data-ok-step-content][hidden]?           (vertical; a Collapse)
[data-ok-stepper-panel="<id>"][data-ok-stepper-panel-step]?   (HTML: shown at its step)
button[data-ok-stepper-next | -back | -reset="<id> …"]       (HTML triggers)

div[data-ok-mobile-stepper][data-ok-variant][data-ok-position][data-ok-steps][data-ok-active-step]
  (back button) · span[data-ok-mobile-stepper-text] | span[data-ok-mobile-stepper-dots][role="img"][aria-label]
  › span[data-ok-mobile-stepper-dot][data-ok-active]? | span[data-ok-linear-progress][data-ok-mobile-stepper-progress] · (next button)
```
The connector sits inside the `li` (an `ol` may only hold `li`; MUI puts it between them unless
`alternativeLabel`).

## Layout and tokens
Horizontal: flex row; steps padding-inline 8px; steps after the first grow and start with their
connector (shrinks to 0 like MUI, 8px before the icon). Icon 24px circle, `--ok-font-size-xs` white number;
not reached `--ok-palette-grey-600` (AA for the white number), active / completed
`--ok-palette-primary-main` (completed shows a check), error `--ok-palette-error-main` with "!".
Title body2, `--ok-text-secondary` / weight regular; active and completed `--ok-text-primary`,
medium; error `--ok-palette-error-text`. Optional caption `--ok-text-secondary`. Line 1px
`--ok-divider`. Alternative label: steps share the width (`flex: 1 1 0`), titles 16px below the
icon, connector absolute at the icon's middle, 8px from each icon. Vertical: label padding 8px 0;
connector 24px tall, 12px in; content 12px in, padding 0 8px 0 20px, 1px line (not on the last
step). `dot`: 22px icon box with an 8px dot, completed check, 3px lines, active / completed lines
primary. `circle`: 50px circles, `rgb(grey-500 / 0.24)`, active / completed gradient
`warning-main → error-main` (active `--ok-shadow-z8`), 3px lines with the gradient.
Mobile: flex, space-between, 8px padding and gap, `--ok-bg-paper`; `bottom` / `top` fixed at
`--ok-z-mobile-stepper` (new token, 1000 like MUI); dots 8px, 2px apart, `grey-500 / 0.8`, active
primary; progress bar 50% wide (LinearProgress `inherit`).

## States
Step flags `data-ok-active`, `data-ok-completed`, `data-ok-disabled` (linear: before / at / after
the active step; explicit Step props win), `aria-current="step"` on the active one; StepLabel
`data-ok-error`; StepContent shows on the active step only: it carries `hidden` on the others
(React from the step context, HTML runtime on every step change) and the Collapse animates its
height (collapse.md); the CSS rule on inactive steps stays for markup without the runtime.

## Behavior
React: `Stepper` clones its direct `Step` children with `index`; each step reads `activeStep`
from context. `activeStep === steps.length` → all completed. HTML runtime `stepper`: derives the
flags from `data-ok-active-step` on mount and on every move; triggers (`data-ok-stepper-next` /
`-back` / `-reset`, several space-separated ids move several steppers) move it; panels
`data-ok-stepper-panel="<id>"` show at their index (or `data-ok-stepper-panel-step`); Back
triggers are disabled on the first step. `mobile-stepper`: updates text, dots (count from
`data-ok-steps`), progress value (`mobileStepperProgress`, MUI rounding) and labels; Back / Next
inside the bar (empty value) or naming it; disabled at the ends; panels
`data-ok-mobile-stepper-panel="<id>"`.

## Keyboard
Steps aren't interactive (MUI linear). The app's Back / Next buttons are native buttons.

## Accessibility
`ol` named by `aria-label`; `aria-current="step"`; icons `aria-hidden` (the title names the step);
mobile dots `role="img"` and the bar named "Step n of m" (`getStepLabel` / `data-ok-label-step`).

## Events / API
HTML `ok:stepper:change` and `ok:mobile-stepper:change` (cancelable) — `detail: { activeStep,
previous }`. Instances → `{ activeStep, setActiveStep(step), go(step) }` (`setActiveStep` emits
nothing). React: no callbacks (the app owns `activeStep`).

## Responsive
Same sizes at every breakpoint. On narrow screens titles wrap inside their steps, and a word
breaks only when it can't fit on its own line (`overflow-wrap: anywhere`), so a horizontal stepper
never overflows; `vertical` or `MobileStepper` read better on phones.

## Parity notes
MobileStepper renders `data-ok-runtime="off"` in React. HTML-only hooks (triggers, panels,
`data-ok-label-step`) are ignored by parity; React demos render the same buttons with handlers.
Stories compose the reference's surfaces: step text in a flat Paper (`elevation={0}`, tinted by
demo CSS), the mobile demos in an outlined Paper with a Divider above the MobileStepper.
