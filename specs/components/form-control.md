# Form control

Reference: MUI API pages "FormControl", "FormLabel", "FormGroup", "FormHelperText" and their demos
on the Radio ("Radio group", "Show error"), Checkbox ("FormGroup") and Switch ("Switches with
FormGroup") pages (content only; Minimals has no page of its own — its Radio "Colors" section
shows a `legend` FormLabel in body2 and the secondary text color). Upstream: MUI `FormControl`,
`FormLabel`, `FormGroup`, `FormHelperText`, `useFormControl` (ADR-0015). Created with `/component`.
Reference URL: https://mui.com/material-ui/api/form-control/
HTML source: written by us (MUI is React only)

## Purpose
Groups a control (or a group of controls) with its label and helper text and shares their states:
`disabled`, `error`, `required`, `focused`, plus `size`, `color`, `variant`, `fullWidth`,
`margin` for a composed input. CSS only: in HTML the states are attributes on the root that the
parts' CSS reads; in React a context (`useFormControl()`) carries them to the parts.

FormControl composes **around** selection controls (Checkbox, Radio, Switch with
FormControlLabel, RadioGroup, FormGroup) and standalone controls (Switch, Slider, Rating…). It
never goes inside TextField, which keeps its own label and helper parts. The controls' DOM and API
don't change: their ARIA (`aria-describedby`, `aria-invalid`, `aria-required`, `disabled`) is
written by the author on them, as in MUI.

## Anatomy
```
(div | fieldset)[data-ok-form-control][data-ok-color]?[data-ok-size]?[data-ok-variant]?[data-ok-margin]?
                [data-ok-full-width]?[data-ok-disabled]?[data-ok-error]?[data-ok-required]?[data-ok-focused]?
                [disabled]?                                          (fieldset: native disabled)
  (label | legend | span)[data-ok-form-label][data-ok-color]?[data-ok-disabled]?[data-ok-error]?
                         [data-ok-required]?[data-ok-focused]?[data-ok-filled]?[id]?[for]?
    …text
    span[data-ok-form-label-asterisk][aria-hidden="true"]?           (required: own or the root's)
  div[data-ok-form-group][data-ok-row]?                              › FormControlLabels
  | div[role=radiogroup][data-ok-radio-group][aria-labelledby][aria-describedby]?
  | a standalone control (its input has id, aria-describedby)
  p[data-ok-form-helper-text][data-ok-margin]?[data-ok-variant]?[data-ok-disabled]?[data-ok-error]?
                             [data-ok-required]?[data-ok-focused]?[data-ok-filled]?[id]?
```
Groups of controls: `fieldset` + `legend` (native group name), or a `div` root with a FormLabel
`id` referenced by the group's `aria-labelledby`. Standalone input: `label[for]`.

Style options are written only when given (a plain group stays `data-ok-form-control` alone).

React: `component` on FormControl (default `div`), FormLabel (`label`), FormHelperText (`p`);
FormGroup `row`. A part's own state props add a state to it (`data-ok-*` on the part); the
FormControl's states reach the parts through CSS in both frameworks, so React writes the root's
states only on the root. FormLabel renders the asterisk when its own `required` or the
FormControl's is on (`required={false}` on the label hides it). `disabled` on a `fieldset`
FormControl is also written as the native `disabled`, which disables every control inside; on a
`div` root, pass `disabled` to each control. `useFormControl()` returns the shared state (or
`undefined` outside a FormControl).

API mapping: see "Upstream API mapping" below.

## Layout and tokens
- Root: `inline-flex` column, `min-width: 0`, no margin / padding / border (a `fieldset` too),
  `vertical-align: top`. `fullWidth` → `width: 100%`. `margin`: dense 8 / 4px, normal 16 / 8px
  (`--ok-spacing` × 2 / 1, × 4 / 2), like TextField.
- FormLabel: body2 (`--ok-typography-body2-*`), `--ok-text-secondary`, no padding; `legend` has
  no float or padding. Focused: `--ok-text-primary` (`color` default) or `--ok-palette-<c>-text`
  (through `--ok-c-text`, read on the root into `--_ok-form-focus`, since `--ok-c-*` don't
  inherit). Error: `--ok-palette-error-text`. Disabled: `--ok-text-disabled` (inactive; exempt
  from contrast like disabled controls). Error wins over focused, disabled over both. Asterisk:
  0.25ch before it.
- FormGroup: flex column, wrap; `row` → row. Same as RadioGroup.
- FormHelperText: caption (`--ok-typography-caption-*`), `--ok-text-secondary`, margin-top 6px
  (`--ok-spacing` × 1.5; dense 4px), inline 0; `outlined` / `filled` variant (own or the root's)
  indent 12px (× 3) like TextField's helper. Error: `--ok-palette-error-text`. Disabled keeps
  `--ok-text-secondary` (AA, as TextField's helper).

## Responsive behavior
Intrinsic: the root shrinks (`min-width: 0`), groups wrap, label and helper text wrap
(`overflow-wrap: anywhere`).

## States / Behavior
None at runtime. States are attributes (and native `:disabled` on a fieldset root).

## Keyboard
The controls' own keyboard behavior. A `legend` / label doesn't take focus.

## Accessibility
- Groups: `fieldset` + `legend` name the group natively; a `div` root needs the group's
  `aria-labelledby` pointing at the FormLabel's `id`.
- Helper text: give it an `id` and reference it from the control or the group
  (`aria-describedby`).
- Error: `aria-invalid="true"` on the radio group or on each checkbox / input; required:
  `aria-required="true"` on a radio group, `required` on an input. The asterisk is `aria-hidden`.
- Label and helper text colors meet AA (4.5:1) except disabled labels (inactive).

## Events / API
None. React `useFormControl()`.

## Contract for Select (batch C; implemented, see select.md and ADR-0045)
Select composes FormControl + an InputLabel without changing this DOM:
- InputLabel = FormLabel (`label[data-ok-form-label][for]` + Select's own part attribute, such as
  `data-ok-input-label`, `data-ok-shrink`) inside the root; its float / shrink styles live in
  Select's CSS (`[data-ok-form-control]:has(> [data-ok-select])`).
- Select reads `useFormControl()` for `disabled`, `error`, `required`, `size`, `color`, `variant`,
  `fullWidth` and writes the resolved values on its own field box and trigger (as MUI's InputBase
  takes them from the context); the FormControl's attributes style the label and helper text.
- Focus and value: the root's CSS uses `:focus-within` / `:has()` on Select's parts in both
  frameworks (no React-only focus state, for parity): the hidden input's `:placeholder-shown`
  tells whether there is a value. No `data-ok-filled` and no context setters were needed.
- `hiddenLabel` (`data-ok-hidden-label`) arrived with Select's filled variant.

## Upstream API mapping
Upstream: MUI `FormControl`, `FormLabel`, `FormGroup`, `FormHelperText`, `useFormControl`.

| Upstream | Owlky | Status | Note |
|---|---|---|---|
| FormControl `children`, `component`, `color`, `disabled`, `error`, `focused`, `fullWidth`, `hiddenLabel`, `margin`, `required`, `size`, `variant` | same | kept | `color` default `default` (MUI `primary`); `hiddenLabel` since Select |
| FormControl `focused` / FormLabel / FormHelperText `filled` tracking | props | renamed | MUI tracks them from its InputBase; here they are props (Select uses CSS `:focus-within` / `:placeholder-shown`) |
| FormLabel `children`, `component`, `color`, `disabled`, `error`, `filled`, `focused`, `required` | same | kept | |
| FormGroup `children`, `row` | same | kept | |
| FormHelperText `children`, `component`, `disabled`, `error`, `filled`, `focused`, `margin`, `required`, `variant` | same | kept | |
| `useFormControl()` | same | kept | `undefined` outside a FormControl |
| context `disabled` / `required` / `error` read by Checkbox, Radio, Switch | — | not applicable | controls' API unchanged by decision; a `fieldset` root disables them natively |
| `sx`, `classes` | — | not applicable | ADR-0015 |
