# Checkbox

Reference: Minimal UI kit "Checkbox" page, sections Basic, Sizes, Custom icons, Placement, Colors,
Indeterminate (content only). Upstream: MUI `Checkbox` (ADR-0015). Created with `/component`.
Reference URL: https://minimals.cc/components/mui/checkbox

## Purpose
Pick any number of options, or accept one statement, in a form. Native `<input type="checkbox">`.
Labels come from `FormControlLabel` (specs/components/form-control-label.md). Used by Table's
selection column.

## Anatomy
```
span[data-ok-checkbox][data-ok-color][data-ok-size][data-ok-indeterminate]?
  input[type=checkbox][data-ok-checkbox-input]   (name, value, checked, disabled, required, aria-*; covers the target, opacity 0)
  span[data-ok-checkbox-icon="unchecked"][aria-hidden="true"] › svg
  span[data-ok-checkbox-icon="checked"][aria-hidden="true"]   › svg (› path[data-ok-checkbox-mark])
  span[data-ok-checkbox-icon="indeterminate"][aria-hidden="true"] › svg (› path[data-ok-checkbox-mark])
```
All three icon slots are always present; CSS shows one. React renders `data-ok-runtime="off"` on
the root. React `ref` and the remaining props go to the **input**; `className` / `style` to the root.

## Layout and tokens
- Target 40px (`--ok-spacing` × 10), icon 24px (× 6); `small` 36px / 20px; `--ok-radius-full`.
- Unchecked `--ok-text-secondary`; checked / mixed `--ok-c-main` (`default` = `--ok-text-primary`,
  mark `--ok-bg-default`; palette marks white); disabled `--ok-action-disabled`.
- Hover (hover-capable): main channel at 0.08 (`default`: `--ok-action-hover`), 150ms.
- Focus-visible: 2px `currentColor` outline inside the target (the reference has none).

## Responsive behavior
Fixed size at every breakpoint; inline-flex, `flex-shrink: 0`. Rows wrap; long label text wraps
inside the label (`overflow-wrap: anywhere`).

## States
From the input via `:has()`: `:checked`, `:indeterminate` or `[data-ok-indeterminate]`,
`:disabled`, `:focus-visible`, plus `:hover`.

## Behavior
Native toggling. React sets `input.indeterminate` from the prop on every render (a click clears
the native flag; the prop stays the truth). HTML runtime `checkbox`:
- mirrors `data-ok-indeterminate` to `input.indeterminate` (mount + attribute changes; a mixed
  state set by other code, such as Table's select-all, is left alone);
- on a user `change`, clears the checkbox's mixed state;
- a checkbox whose input has `aria-controls="<ids>"` is a **parent** (WAI-ARIA mixed checkbox):
  its change checks / clears every listed checkbox; any listed checkbox's change recomputes the
  parent (`selectAllState`: all → checked, some → mixed, none → clear), up nested parents.
  Ids resolve in the input's root (shadow-safe); unknown ids and cycles are ignored.
Without the runtime: toggling and the `data-ok-indeterminate` icon work; `aria-checked=mixed` and
parents don't.

## Accessibility
Native checkbox: name from the label, `aria-label` or `aria-labelledby`; mixed via
`indeterminate`. Icons are `aria-hidden`. Brand colors follow the reference (ADR-0014).

## Events / API
HTML: native `change` (only the checkbox the user changed; children updated by a parent fire
none). No instance methods. React: `onChange(checked)`, `checked` / `defaultChecked`.

## Parity notes
HTML parents (`aria-controls`) are runtime behavior; React apps compute the state
(`selectAllState`) as the Indeterminate story does.
