# Scroll progress

Reference: Minimal UI kit "Scroll progress" page, sections "Container scroll-y", "Container
scroll-x" and "Scroll document" (content only). Upstream: Framer Motion `useScroll` (ADR-0015).
Roadmap Phase 5, step 5.2 of the Motion full version (ADR-0062, note of 2026-11-11). Created with
`/implement`. Not a component of its own: Linear and Circular progress follow a scroll position.
Reference URL: https://minimals.cc/components/extra/scroll-progress

## Purpose
Shows how far a scroll container, the page or one element on the way through it has been
scrolled, with a Linear or Circular progress. Reading indicators on articles, long lists and
horizontal galleries.

## Anatomy
```
span[data-ok-linear-progress | data-ok-circular-progress][data-ok-variant="determinate"]
    [role=progressbar][aria-hidden="true"]
    [data-ok-scroll-progress]                                   follows a scroll position
    [data-ok-scroll-axis="x"]?                         default y
    [data-ok-scroll-container=<id>]?                   default: the page (the root scroller)
    [data-ok-scroll-target=<id>]?                      default: the container's whole content
    [data-ok-scroll-offset="<edges>, <edges>"]?        default "start start, end end"
    [data-ok-fallback]?                                written by the script fallback (below)
  …the progress's own parts (unchanged)
```
No `aria-valuenow` / `-valuemin` / `-valuemax` (see Accessibility). React renders
`data-ok-runtime="off"` on the root, as the progress components do.

| Framer `useScroll` | React (`scroll` prop of LinearProgress / CircularProgress, `useScroll()`) | HTML |
|---|---|---|
| `container` (ref, default the page) | `container`: a ref or an element id | `data-ok-scroll-container="<id>"` (unknown id → the page) |
| `target` (ref, default the container's content) | `target`: a ref or an element id | `data-ok-scroll-target="<id>"` |
| `axis` (`y`) | `axis` | `data-ok-scroll-axis` |
| `offset` (two intersections) | `offset`: `[ScrollIntersection, ScrollIntersection]` or a string | `data-ok-scroll-offset`: the two, comma separated |
| returns `scrollX`, `scrollY`, `scrollXProgress`, `scrollYProgress` (motion values) | `useScroll()` returns them as numbers (state); the progress shows the `axis` one | instance `progress` |

An offset is two intersections of the target and the container, each `"<target> <container>"`
(Framer): an edge is `start`, `center`, `end`, a number (0–1 of the size), `<n>px`, `<n>%`,
`<n>vw` or `<n>vh`; one edge applies to both; React also takes `[target, container]` pairs of
numbers. Progress is 0 at the first intersection and 1 at the second, clamped. Defaults: `start
start, end end` (the whole scroll range of the container, or the target from touching the
container's start to its end touching the container's end). Invalid entries → the default.

React: `scroll` is `true` (the page, vertical) or an object of the options above. With `scroll`,
the variant defaults to `determinate` and `value`, `min` and `max` are ignored. Linear and
Circular progress became client components (`"use client"`: the effect that follows the scroll);
they still render on the server.

## Layout and tokens
The progress keeps its own look (size, thickness, color, track). Linear bar 1 and the Circular
arc read `--_ok-scroll-progress` (a registered `<number>`, 0–1) instead of the value, with no
value transition (the bar follows the scroll; smoothing springs are deferred to 5.4). Circular
arc: `stroke-dasharray` = π × (44 − thickness) px, offset `(1 − progress) ×` that. Stories
(layout only, `.storybook/preview.css`): a 32px Circular with its track at the end of the row,
the Linear under it, then the Scrollbar of numbered Cards (the reference's `info` color for
"Container scroll-y", `inherit` for "Container scroll-x"); the page progress is `position: fixed`
at the top (`--ok-z-mobile-stepper`).

Intentional differences from the reference: one-color bars (the reference fills its Linear bars
with a gradient; the Linear progress has no gradient fill), the progress's own 4px height
everywhere (the reference draws 3px in containers and 6px for the page), and no smoothing spring.

## Behavior
Core `createScrollProgress(element, options)` (both owners) picks a path:
1. **CSS** (`@supports (animation-timeline: scroll())`, no container, target or offset): the
   stylesheet animates `--_ok-scroll-progress` with `animation-timeline: scroll(root y | x)`.
   Works without JavaScript (HTML before the runtime, React before hydration). The controller
   does nothing.
2. **Native timeline** (`ScrollTimeline` and the CSS feature supported): the engine's
   `animate()` (ADR-0062) plays the property on a `ScrollTimeline({ source: container, axis })`
   (no target, default offset) or a `ViewTimeline({ subject: target, axis })` with `rangeStart` /
   `rangeEnd` when both intersections are named edges that a range expresses exactly
   (`start end` → `cover 0%`, `end end` → `entry-crossing 100%`, `start start` →
   `exit-crossing 0%`, `end start` → `cover 100%`) and the target's nearest scroll container is
   the container. Off the main thread; no inline style on the author's container or target.
3. **Script fallback** (Firefox 128+, Safari 17–18, or offsets a range can't express):
   `data-ok-fallback` on the element; `animate()` plays the same keyframes paused and a passive,
   rAF-throttled scroll listener (container or window) plus a ResizeObserver (container, target)
   sets its `currentTime` from the measured progress.
Teardown (`destroy`, React unmount, runtime stop) cancels the animation and removes listeners,
observers and `data-ok-fallback`. Option changes rebuild the controller (React: the effect's
dependencies; HTML: a MutationObserver on the `data-ok-scroll-progress*` attributes). Right to left: `x`
progress follows the inline direction (`|scrollLeft|`). Reduced motion: the bar keeps following
the position (it is not an animation of its own; the engine runs with `reducedMotion: "never"`).

## Keyboard
None (not focusable). The scroll container keeps its own keyboard scrolling (Scrollbar).

## Accessibility
Decorative: `aria-hidden="true"` on the progress (React adds it with `scroll`), no `aria-value*`.
Why: the reference's indicators have no role; the position is already exposed by the scroll
container itself (a focusable, named region whose scrolling assistive technology reports), and a
progressbar that changed on every frame would either be noisy or (CSS and native paths, which
never run script per frame) carry a stale `aria-valuenow`. axe stays green (hidden elements are
not checked for a name). Authors who need an announced position add their own text.

## Events / API
HTML runtime `scroll-progress` (selector `[data-ok-scroll-progress]`, next to the progress's own runtime):
instance `{ readonly progress: number; readonly mode: "css" | "native" | "fallback"; update() }`;
no events (Framer's per-frame `change` would fire on every frame: read `progress` when needed).
React: `scroll` prop on LinearProgress and CircularProgress; `useScroll(options)` →
`{ scrollX, scrollY, scrollXProgress, scrollYProgress }` (re-renders on scroll, rAF-throttled).
Core: `createScrollProgress`, `observeScroll(options, callback)`, `measureScroll`,
`parseScrollOffset`, `readScrollProgress(element)`, `scrollProgressAttributes`,
`supportsScrollTimeline` (`setScrollTimelineSupport` for tests).

## Responsive
Nothing changes per breakpoint; the Linear bar fills its row, the Circular keeps its size.
