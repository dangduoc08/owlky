# Illustration

Reference: the illustrations of the Minimal dashboard (error pages 403 / 404 / 500, maintenance,
coming soon, empty content, upload, order complete, sign in, verify / reset password, dashboard
welcome, upgrade, avatar shape), content and style only: every picture is original artwork
(ADR-0041). Foundation: Storybook › Foundations › Illustrations.
Reference URL: https://minimals.cc/error/404 (no components page; the pictures also appear on
/error/403, /error/500, /maintenance, /coming-soon and the dashboard).
HTML source: written by us

## Purpose
A theme-aware illustration set. Each illustration is data (a tree of SVG nodes) whose shapes name
a tone instead of a color; the stylesheet maps tones to `--ok-*` tokens, so pictures follow the
color scheme, nested themes, `data-ok-preset` and the `color` option. One export per picture in
the opt-in entry `@owlky/core/illustrations` (tree-shaken). Components that show decorative art
compose it (Upload's drop zone).

## Style
Every scene follows `docs/illustrations-style.md` (canvas, composition, tones, strokes, people,
detail) and composes the parts of `@owlky/core/illustrations` (`backdrop`, `groundShadow`,
`sparkle`, `dot`, `cloud`, `plant`, `lines`, `paper`, `screen`, `person`;
`core/src/illustrations/parts.ts`). Parts set `part` on their first node (data only, never
rendered); `core/src/illustrations/style.test.ts` enforces the guide. New pictures: `/illustration`.

## Anatomy
```
svg[data-ok-illustration="<name>"][data-ok-color][data-ok-size]?[viewBox][focusable="false"]
   [aria-hidden="true"] | [role="img"][aria-label | aria-labelledby]
  title?                                   (React `title`)
  (g[transform]? › …) | path | circle | ellipse | rect | polygon | polyline | line
    [data-ok-tone="<tone>"][data-ok-stroke][stroke-width]?  geometry attributes only
```
- Elements: `g path circle ellipse rect polygon polyline line` (`illustrationTags`); attributes:
  geometry, `transform`, `opacity`, `fill-rule`, `stroke-dasharray` (`illustrationAttributeNames`).
  Never `href`, `use`, `image`, `foreignObject`, `script`, `style`, ids or colors.
- Every shape has a tone; groups never do. `data-ok-stroke` paints the tone as the outline
  (`stroke-width` from the data), with round caps and joins.
- Tones (`illustrationTones`): brand `lighter light main dark darker` (the `color` palette),
  accent `accent-light accent-main accent-dark` (warning palette), scheme-aware `paper neutral
  outline line shadow shade ink`, fixed `grey-300 grey-500 grey-600 white`, skin `skin-light
  skin-medium skin-deep` (`--ok-illustration-skin-*` tokens).
- Scenes use `viewBox="0 0 480 360"`; shapes (`avatar-shape`) their own.
- React renders `data-ok-runtime="off"` and the private `--_ok-illustration-size` in `style`.

Other props: `illustration` (required: the data, an export of `@owlky/core/illustrations` or your
own `Illustration` object), `title` (accessible name: `role="img"`, `aria-label` and a `<title>`),
`aria-label` / `aria-labelledby` (also make it `role="img"`), `ref`, `className`, `style` and other
SVG attributes (go to the `svg`). HTML: a `width` attribute sizes the picture without the runtime.

## Layout and tokens
`display: block`, `max-width: 100%`, `height: auto` (the viewBox keeps the ratio). Width: the
`width` attribute, else `--_ok-illustration-size` (size option), else 480px
(`calc(var(--ok-spacing) * 120)`). Brand tones read `--_ok-illustration-<shade>` declared on the
root from `--ok-palette-<color>-<shade>`, so a root inside a `[data-ok-preset]` / `[data-ok-theme]`
scope takes that scope's values. `ink` is `light-dark(grey 800, grey 600)` inside
`@supports (color: light-dark(#000, #fff))` (grey 800 otherwise). Translucent tones use
`rgb(var(--…-channel) / α)`.

## Behavior
- React: renders the tree as elements (attribute names camelCased); invalid nodes / attributes /
  tones are dropped (`illustrationNodeAttributes`, `illustrationChildren`).
- HTML snippets: the full inline SVG (generated from React,
  `node apps/storybook/scripts/illustration-snippets.mjs`); CSS only, no JavaScript.
- HTML runtime (opt-in: `owlky-illustrations.js`, `@owlky/html/illustrations`, or
  `createIllustration([…])`): on `svg[data-ok-illustration]` without artwork, builds the named
  picture with `createElementNS` and sets `viewBox`; artwork already there (snippets, custom art)
  stays. Writes `aria-hidden="true"` unless the author named it (then `role="img"`), and
  `focusable="false"`. Turns `data-ok-size` into `--_ok-illustration-size` (CSSOM) and follows
  changes of `data-ok-size` and of the name (redrawing what it drew). Unknown names: nothing drawn.

## Keyboard
None: illustrations never take focus.

## Accessibility
Decorative by default (`aria-hidden="true"`, `focusable="false"`). Meaningful pictures get a name
(`title` / `aria-label` / `aria-labelledby` → `role="img"`). No text inside the art. Decorative
art has no contrast requirement (axe passes in light and dark).

## Events / API
HTML instance: `runtime.get(svg, "illustration").illustration` (the data drawn, or `undefined`).
Core: `illustrationAttributes(name, options)`, `illustrationNodeAttributes(node)`,
`illustrationChildren(nodes)`, `illustrationStyle(size)`, `illustrationAria(named, title?)`.
`@owlky/core/illustrations`: the pictures, `illustrations`, the parts (pure functions returning
nodes; numbers and tones only) and `illustrationParts` (the `part` names).

## Upstream API mapping

No upstream: the set is original artwork and API (ADR-0041); nothing to map.

## Parity notes
Snippets carry the shapes; the runtime draws the same markup for named placeholders (tested).
`style` is ignored by parity (React's private size property; the runtime's CSSOM).
