# Scrollbar

Reference: Minimal UI kit "Scrollbar" page, sections "Vertical", "Horizontal", "Layout" (content
only). Upstream: simplebar (ADR-0015). Created with `/component`.
Reference URL: https://minimals.cc/components/extra/scrollbar

## Purpose
A scroll area with themed, thin scrollbars that stay out of the way until needed. Table, Drawer
and Sortable scroll through it (see Anatomy).

## Anatomy
```
section[data-ok-scrollbar][aria-label][tabindex=0][data-ok-auto-hide="false"]?   (named section = region)
  …content (the root itself scrolls: overflow: auto)
```
Used by other components by composition (their CSS adapts when it wraps a Scrollbar):
`TableContainer › Scrollbar › Table`, `DrawerContent › Scrollbar › …`, `Scrollbar › Sortable`.

Name and focus: `aria-label` (default `"scrollable content"`, as upstream `ariaLabel`; skipped
when `aria-label` / `aria-labelledby` is given) and `tabIndex` (default `0`). Upstream
`forceVisible`, `clickOnTrack`, `scrollbarMinSize` / `scrollbarMaxSize`, `direction`, `timeout`,
`classNames`, `recalculate()` and `getScrollElement()` don't apply: the scrollbars are native
(`overflow`, `dir` and the browser cover them) and the root is the scroll element (React `ref`).

## Layout and tokens
- Thumb: `text.disabled` at 48 % — `rgb(--ok-palette-grey-500-channel / 0.48)` (light),
  grey 600 (dark, via `light-dark()`; light tone without it); track transparent.
- Standard path (`@supports (scrollbar-color: auto)`): `scrollbar-width: thin`,
  `scrollbar-color: <thumb> transparent`.
- Fallback (`::-webkit-scrollbar`, Safari and Chrome < 121): 11px track
  (`--ok-spacing` × 2.75), thumb inset 2px (× 0.5) with `--ok-radius-full`, min 10px (× 2.5).
- Focus-visible: 2px `--ok-text-primary` outline, inset.

## States
- Auto-hide (default): thumb transparent at rest; visible on `:hover` (hover-capable devices)
  and `:focus-within`. Touch screens (`hover: none`): always visible.
- `data-ok-auto-hide="false"`: always visible.

## Behavior
CSS only, no runtime. Scrolling is native (wheel, touch momentum, keyboard, find-in-page).

## Keyboard
Tab focuses the area; arrow keys, Page Up / Page Down, Home / End and Space scroll it (native).

## Accessibility
- A named `<section>` (role `region`), focusable (axe `scrollable-region-focusable`).
- The thumb shows while focus is inside, so keyboard users see the position.

## Events / API
None. React: `ref` is the scroll element.

## Parity notes
None: React renders the same element and attributes as the snippets.

## Intentional differences from the reference
1. Native scrollbars take layout space where the OS uses classic scrollbars (Windows, Linux);
   simplebar overlays them.
2. On the standard path (Firefox, Chrome 121+) the browser draws the thin thumb's shape and width.
3. No "visible while scrolling, fade out after 0.5s": CSS can't detect scrolling; the thumb shows
   on hover and focus instead.
4. iOS / Android show the system's overlay scrollbars.

## Responsive
Mobile first, no breakpoints: the area fills its container (`min-width: 0`); content wraps or
scrolls inside. The Layout story stacks Top / Left / content / Right / Bottom below 900px and uses
three columns from 900px (story-only demo CSS).
