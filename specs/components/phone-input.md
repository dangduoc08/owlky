# Phone input

Reference: Minimals "Utilities" page, section "Phone input": Auto, Default value, Default
country, Fixed country, Fixed country + international, Fixed country + international +
hideSelect (a text field with a country select, and the national, international and raw values
under it; content only). Upstream: react-phone-number-input (catamphetamine,
gitlab.com/catamphetamine/react-phone-number-input) on libphonenumber-js, mapped prop by prop
below (ADR-0015). Created with `/implement` (roadmap 4.25).
Decision record: ADR-0061 (libphonenumber-js `min`, opt-in entries, a bare Select of countries).
Reference URL: https://minimals.cc/components/extra/utilities
HTML source: written by us (react-phone-number-input is React only)

## Purpose
Enter a phone number of any country: a country select with flags in the field, formatting as you
type, an E.164 value (`+61298765432`) with its national and international forms, and an optional
validation state for the helper text. Opt-in: the phone metadata (libphonenumber-js `min`, about
35 kB gzip) loads only with `@owlky/core/phone` (`@owlky/html/phone`, the CDN's lazy
`modules/phone-input.js`, ADR-0068).

### Image flags (ADR-0070 section 9)
Flags are emoji by default and cost no bytes, but Windows shows flag emoji as two letters.
`flags="image"` / `data-ok-flags="image"` draws **Circle Flags** instead (HatScripts/circle-flags,
MIT): one round SVG per country, never a bundle. The build copies `circle-flags`' two-letter files
(`au.svg`, lowercase ISO code, and `xx.svg`, the set's unknown-country flag) and its license into
`@owlky/html/dist/flags/`, a folder you can host yourself. The folder is `flagsPath` /
`data-ok-flags-path` (a relative, root-relative or `http(s)` URL; a trailing `/` is added):
- **CDN bundle:** the phone module defaults it to `flags/` next to `owlky.js`.
- **Bundlers and React:** there is no default (the `@owlky/html/phone` entry sets none) (`import.meta.url` does not survive bundling): copy
  the folder and pass `flagsPath`. Without a folder (or with an unsafe one) the flags stay emoji.
- The image URL is only `<folder><code>.svg` with a code matching `^[a-z]{2}$` (core
  `phoneFlagSource`); folders with another scheme (`javascript:`, `data:`), whitespace, quotes or
  angle brackets are refused. The HTML component's `setPhoneFlagsPath` sets the default folder (the CDN module does).
- Each flag is `<img data-ok-phone-input-flag-image alt="" loading="lazy" decoding="async">`
  inside the `data-ok-phone-input-flag` span, in the trigger and in every option; the country name
  stays text. The International option keeps the globe. React renders the same markup as the
  HTML runtime (built with DOM methods).

## Layout and tokens
The TextField look. The country select sits in the start adornment: the flag (`--ok-font-size-xl`
emoji, 24px box; the globe and an image flag 20px), 4px padding, the arrow (16px, `--ok-text-secondary`) after it,
then 8px and a 1px `--ok-divider` line before the input. A fixed country or a disabled field shows
the flag alone (no arrow); a disabled field dims it to 0.48. The list is a Popover of MenuItems,
320px wide (at most the viewport less 32px), at most 400px high, scrolling: each option is the
flag, the name (subtitle2) and "AU (+61)" (body2, secondary). The field's trigger keeps the name
and code visually hidden (the combobox's value for screen readers).

## Responsive behavior
Intrinsic, as TextField (`fullWidth` stretches it). The list keeps 16px inside the viewport.

## States / Behavior
Model in `@owlky/core/phone` (pure): `phoneInputSettings` / `readPhoneInputSettings`,
`phoneInputChange(text, caret, country, settings)` (digits, country, formatted text, value,
caret), `phoneCountryDigits` (a pick), `phoneDigitsFromValue`, `phoneCountryOfValue`,
`phoneValueDetails`, `phoneCountryOptions`, `phoneFlag`. Core
`createPhoneInputController(input, { onInput }, { input? })` reports typed text with the caret;
Backspace / Delete next to a formatting character remove the nearest digit (`beforeinput`).
- **Auto** (no country): typing starts an international number (a `+` is added); the country of
  the calling code is selected as soon as it is known (`+84` → Vietnam; a shared code such as `+1`
  keeps the selected country when it shares it, otherwise International).
- **Default country**: national digits are read as that country's (`(02) 9876 5432` for AU);
  typing `+` switches to international digits and their country.
- **Fixed country** (`country`): the select is disabled and shows the flag only; national form
  (a pasted `+61…` number of that country is shown nationally) or, with `international`, the
  calling code stays in front (`+61 2 9876 5432`; deleting it puts it back).
- **International** with a selected country and `countryCallingCodeEditable` off: the same
  locked calling code.
- **A pick** rewrites the digits for the new country: international digits of the old country
  get the new calling code (international form) or are cleared unless they belong to the new
  country (national form); International turns national digits into the old country's
  international number. The focus moves to the input (`focusInputOnCountrySelection`).
- `limitMaxLength` drops digits typed past the country's longest number.
- **Validation** (`validate`): after the input loses focus once, a non-empty number that isn't
  valid (`isValidPhoneNumber`, `min` metadata) sets the error state (`data-ok-error`,
  `aria-invalid`) and shows `invalidText` in the helper text (the original text comes back when
  it is valid). The change details always carry `valid` / `possible` for your own checks.
- HTML runtime `phone-input` (opt-in, `OPT_IN`): fills the empty listbox with DOM methods (the
  markup React renders), reads the selected country from the Select's hidden input (else the
  fixed or default country) and the digits from the input's text, writes the text, the caret and
  the Select's value (`setValue`), listens to `ok:select:change`, re-reads the settings when a
  root option attribute changes, and disables the select with the input (`disabled`, `readonly`).

## Keyboard
| Key | Action |
|---|---|
| Typing, paste | Digits and a leading `+` are kept and formatted; other characters are dropped |
| Backspace / Delete | Remove the digit before / after the caret (formatting characters are skipped) |
| Tab | From the country select to the input |
| Country select | The Select's keys (select.md): Arrow keys, Home / End, typeahead on names, Enter / Space, Escape |

## Accessibility
Two tab stops: the country combobox (named "Country", `labels.country`; its value is the selected
option's visually hidden name and code) and the `tel` input named by the label (`autocomplete="tel"`
for autofill). Flags are `aria-hidden` (emoji names would repeat the country); image flags are `alt=""` inside
that span. The helper text
describes the input; with `validate`, the error state is `aria-invalid` and the helper text says
why. A fixed country's select is `aria-disabled` and out of the tab order.

## Events / API
HTML: `ok:phone-input:change` (`{ value, national, international, country, valid, possible }`)
after the number changed; `ok:phone-input:countrychange` (`{ country }`, `undefined` =
International). Instance `{ value, setValue(value), country, setCountry(country), details }`
(setters emit no events). React: `onChange(value, details)`, `onCountryChange(country)`.

### Intentional differences from the reference
- Flags are emoji by default (Windows shows the two letters); `flags="image"` draws Circle Flags
  from a folder you host, never from a third-party CDN.
- The country list has no search box: the Select's typeahead finds a country by name.
- Typing `+84…` in Auto keeps the international text (upstream behavior); the reference rewrites
  it in national form. The national form is in the change details.
- No clear button: pass an `endAdornment` if you want one.
