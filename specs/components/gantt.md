# Gantt

Reference: ApexCharts' ApexGantt (commercial product: behavior, options and API only; no code,
demo data, images or text copied), its demos and docs. ADR-0048. Phase 1 of 3: a read-only
Gantt — scales and zoom, bars, summary tasks, milestones, baselines, the critical path, the tree,
dependencies, non-working days, the today line, selection, tooltips and the keyboard. Created with
`/component`.
Reference URL: https://apexcharts.com/apexgantt/
HTML source: written by us (ApexGantt is a commercial product; ADR-0048)

## Purpose
Show a project's tasks on a timeline: a task list (name, dates, duration, progress) and a timeline
with one bar per task in the same rows, the hierarchy of summary tasks, milestones and the
dependencies between tasks. One core layout (`renderGantt`) draws it for React and HTML.

## States
`aria-expanded` on parent rows (`data-ok-collapsed` on their table rows), `aria-selected` with
`selection` (`data-ok-selected`), the roving `tabindex="0"` on the active row, `data-ok-ready`,
the zoom in `data-ok-pixels-per-day`.

## Behavior
- **Dates:** ISO days as UTC day numbers; the end day is included; a task without `endTime` (and
  without children) is a milestone at `startTime`. Parents become summary tasks: their dates span
  their children, their progress is the duration-weighted mean of their leaf tasks.
- **Scale:** `view` presets the zoom (`day` 36, `week` 16, `month` 5, `quarter` 1.6, `year` 0.5 px
  per day); `pixelsPerDay` overrides it. Two header tiers from the zoom: month / day (≥ 24),
  month / week (≥ 8), year / month (≥ 2.5), year / quarter (≥ 0.9), year / half. The range starts
  one bottom unit before the first task and ends one after the last. Zoom buttons multiply or
  divide by 1.4 (0.25–120).
- **Background:** non-working days shaded from 8 px per day, column lines at bottom-tier units,
  row lines, a today line, dashed project boundary lines, dependency arrows (orthogonal, rounded
  corners, an arrow head; critical links in the error color).
- **Critical path:** a backward pass from the project's end over the dependencies (calendar days),
  tasks and milestones with no total float, links with no slack.
- **Labels:** `right` (default), `left`, `inside` (clipped), `auto` (inside when the estimated
  width fits). Milestones are always labeled outside; summaries have no bar label.
- **Controller** (`createGanttController`, both implementations): row focus (roving tab stop, a
  row focused another way becomes active), expand / collapse, selection, zoom buttons, tooltip.
  It reports intent; React keeps state in props / state, the HTML runtime in the table and the
  root, after a cancelable event.
- **Responsive:** one scroll container; the header and the task list are sticky. Below 600px of
  the Gantt's own width (container query) only the name column shows, at most 40% of the width.

## Keyboard
| Key | Action |
|---|---|
| Tab | into the grid (the active row), then out of it |
| ↓ / ↑ | next / previous row |
| Page Down / Page Up | 10 rows down / up |
| Home / End | first / last row |
| → | expands a collapsed parent; on an expanded parent, moves to its first child |
| ← | collapses an expanded parent; otherwise moves to the parent |
| Enter | toggles a parent |
| Space | toggles the row's selection (`selection`); Shift + Space selects the range |
| Shift + ↓ / ↑ / Page / Home / End | extends the selection (`selection`) |
| Ctrl / Cmd + A | selects every row (`selection`) |
| Escape | hides the tooltip (wherever the focus is); cancels a drag |
| Enter (editable task row) | starts the edit mode: ← / → move a day, Shift + ← / → change the end, Page Up / Page Down ±10 % progress, Enter saves, Escape (or Tab) cancels; other arrows stay in the mode |
| F2 (editable task row) | asks for the owner's edit form (`onTaskEdit`, `ok:gantt:edit`) |

Pointer: a click focuses a row and selects it (Ctrl / Cmd toggles, Shift selects the range); the
chevron toggles a parent; hovering a bar shows the tooltip, which stays while hovered.

## Accessibility
- `role=treegrid` named by `label` (the table caption in HTML), `aria-rowcount` / `aria-colcount`,
  rows with `aria-level`, `aria-posinset`, `aria-setsize`, `aria-expanded`, `aria-selected`.
- Each bar is `role=img` named with the task, its dates, progress, planned dates (baseline), the
  critical path and its predecessors with the dependency type and lag. Labels, the scale and the
  SVG are `aria-hidden` (the header names the timeline column "Timeline").
- The tooltip repeats the row's data (`aria-hidden`), shows on keyboard focus too, stays while
  hovered and closes with Escape (WCAG 1.4.13).
- Color is never the only cue: critical tasks and links are also named; milestones are diamonds.
- Text uses neutral tones (AA); bars are graphics (palette fills, 3:1 against the paper).

Editing (`editable`, phase 2): editable task bars carry `span[data-ok-gantt-handle="start|end|progress"]`
(aria-hidden), rows `aria-keyshortcuts="Enter F2"`; drag the bar (move), an edge (resize, at least a
day) or the progress handle (whole percents); 3 px before a drag starts; the preview is CSSOM on the
bar (`data-ok-dragging`), undone before the change is reported, so the owner's render decides.
Milestones move only; summaries never edit. Touch: `touch-action: none` on editable bars. Double
click / double tap / F2 → `onTaskEdit` (the single-pointer path, WCAG 2.5.7). The edit mode
announces its keys and each draft in `div[data-ok-gantt-status][role=status]` (last child of the
root). Right to left mirrors the arrows and drags.

## Events / API
HTML events: `ok:gantt:taskchange` (cancelable; `{ id, change: { startTime, endTime?, progress? }, source:
"drag" | "resize" | "progress" | "keyboard" }`; then the runtime writes the table row), `ok:gantt:edit`
(`{ id }`), `ok:gantt:toggle` (cancelable; `{ id, expanded, collapsed }`),
`ok:gantt:selectionchange` (cancelable; `{ selected, mode }`), `ok:gantt:zoom` (cancelable;
`{ pixelsPerDay }`). Instance (`runtime.get(el, "gantt")`): `tasks`, `collapsed`,
`setCollapsed(ids)`, `selected`, `setSelected(ids)`, `pixelsPerDay`, `zoomIn()`, `zoomOut()`,
`scrollToTask(id)`, `setLocaleText(text)`, `refresh()`.
React: `onCollapsedChange(ids)`, `onSelectionChange(ids, mode)`, `onZoomChange(pixelsPerDay)`;
controlled `collapsed`, `selected`, `pixelsPerDay` with `default…` counterparts.

## Parity notes
React renders the same table and treegrid the runtime builds (one core node tree); the SVG and the
private properties are compared by `e2e/tests/gantt.spec.ts` (parity doesn't walk into SVG or
`style`). The tooltip's content is written by the controller in both.
