Autoplay, Auto Scroll, Thumbs-x, Thumbs-y, Variable widths, Auto height, Y-axis, Dots number,

Reference URL: https://minimals.cc/components/extra/carousel
HTML source: written by us

## Purpose
Show a set of slides one view at a time; people swipe, scroll, drag, use the arrow keys or the
controls. The viewport is a native scroll container with CSS scroll snapping (works without
JavaScript); core `createCarouselController` adds Embla's options and plugins and writes the
derived state (selected snap, slides in view, controls) for React and the HTML runtime alike.

Every control can sit anywhere inside the root (several sets at once). React parts: `Carousel`,
`CarouselStage`, `CarouselViewport`, `CarouselSlide`, `CarouselArrows`, `CarouselDots`,
`CarouselProgress`, `CarouselThumbs`, `CarouselThumb`, `CarouselPlayButton`.

Outside the schema:
- `align`: also a number 0–1 (`data-ok-align="0.1"`), and in React a function
  `(viewSize, snapSize, index) => offset`.
- `slidesToShow`: a number (`2`, `1.5`), a percentage (`"70%"`) or `"auto"` (the slide's own size),
  per breakpoint `{ xs, sm, md, lg, xl }` → `data-ok-slides-to-show`, `-sm`, `-md`, `-lg`, `-xl`
  (600 / 900 / 1200 / 1536px). Sizes become `--_ok-carousel-basis-*` (React `style`, HTML CSSOM).
- `slidesToScroll="auto"`; `containScroll={false}` → `data-ok-contain-scroll="false"`.
- `breakpoints`: Embla's media query → options object (`active`, `align`, `loop`, `dragFree`,
  `draggable`, `dragThreshold`, `skipSnaps`, `containScroll`, `slidesToScroll`, `duration`,
  `inViewThreshold`, `autoplay`, `autoScroll`, `wheelGestures`), JSON in `data-ok-breakpoints`;
  invalid keys and values are dropped.
- `direction` (Embla) is the `dir` attribute of the root or an ancestor.
- Parts: `CarouselArrows` `prevLabel` / `nextLabel` (default "Previous slide" / "Next slide"),
  `prevIcon` / `nextIcon`; `CarouselDots` `getLabel(index)` (default "Go to slide n");
  `CarouselThumb` `aria-label` (default "Go to slide n"); `CarouselPlayButton` `playLabel` /
  `pauseLabel` and every Button prop (default contained, primary, small).

## States
Written by the controller (React renders only the initial state from `startIndex`):
`data-ok-snapped` / `data-ok-in-view` on slides, `aria-current="true"` on the selected dot and
thumbnails, `aria-disabled="true"` on arrows that can't move, the counter text, the live region
text and `aria-live` (`off` while playing), root flags listed in the anatomy, and private custom
properties: `--_ok-carousel-snap*`, `-order`, `-tween`, `-parallax`, `-progress`, `-height`,
`-lead` / `-trail`, `-duration`.

## Behavior
- Snaps: groups of `slidesToScroll` (or as many as fit), aligned by `align`, contained by
  `containScroll`; the browser snaps to the same positions (per-slide snap alignment and margins).
- Selection follows the scroll position (nearest snap); `select` fires when it changes, `settle`
  when scrolling stops (120 ms after the last scroll event).
- Animated scrolls last `duration × 20` ms with an ease-out; instant with reduced motion or `jump`.
- Mouse: drag scrolls; release moves one snap in the drag direction (`skipSnaps`: by velocity,
  `dragFree`: momentum). Clicks after a drag longer than `dragThreshold` are prevented. Touch, pen
  and trackpads scroll natively (`skipSnaps` off = `scroll-snap-stop: always`).
- Loop (ADR-0033): the visual order rotates through CSS `order`; no clones; falls back when the
  content is shorter than one viewport plus two steps. The rotation puts the selected snap in the
  middle of the scroll range (by length, not by count); jumps rotate around the target, animated
  moves around the middle of the shortest way.
- Fade: slides stacked; swipes step; hidden slides are `visibility: hidden`.
- Effects: `opacity`, `scale` (the slide's child) and `parallax` (`[data-ok-carousel-parallax]`).
- Focus inside a slide scrolls to its snap (`focus`).
- Autoplay: every `autoplayDelay`, next snap (wraps to the first); pauses on hover, stops on
  focus, pointer down and wheel; `stopOnInteraction={false}` pauses until it settles.
- Auto scroll: `autoScrollSpeed` px per frame after `autoScrollStartDelay`; same interactions.
- The play button toggles autoplay (or auto scroll when only that is on).
- Auto height: the viewport height follows the tallest selected (or in-view) slide.
- Resize, slide changes, option attributes and matching breakpoints re-initialize the carousel.
  A scroll frame or a settle that finds the sizes changed re-initializes first (a resize can
  re-snap the viewport before the ResizeObserver reports it); a running animation is retargeted.

## Accessibility
WAI-ARIA APG carousel: labelled `section` (region) with `aria-roledescription="carousel"`, slides
as `group`s with `aria-roledescription="slide"` and "n of total" labels; arrows stay focusable at
the ends (`aria-disabled`); the live region announces moves the user makes, never autoplay; autoplay
and auto scroll have a play / pause control, pause on hover and stop on focus (WCAG 2.2.2) and
never start with `prefers-reduced-motion`. Loop never duplicates content. Dots and thumbnails are
24px and larger (WCAG 2.5.8).

## Events / API
HTML events on the root: `ok:carousel:select` `{ index, previous }`, `settle` `{ index }`,
`scroll` `{ progress }`, `slidesinview` `{ indexes }`, `reinit` `{ snapCount }`, `autoplay` /
`autoscroll` `{ playing }`, `slidefocus` `{ index }`, `pointerdown`, `pointerup`.
Instance (`runtime.get(root, "carousel")`) and React `apiRef`: `scrollNext(jump?)`,
`scrollPrev(jump?)`, `scrollTo(index, jump?)`, `canScrollNext()`, `canScrollPrev()`,
`selectedScrollSnap()`, `previousScrollSnap()`, `scrollSnapList()`, `scrollProgress()`,
`slidesInView()`, `slidesNotInView()`, `slideNodes()`, `rootNode()`, `containerNode()`, `reInit()`,
`autoplay.{play, stop, reset, isPlaying, timeUntilNext}`, `autoScroll.{play, stop, reset, isPlaying}`.
React callbacks: `onSelect(index, previous)`, `onSettle(index)`, `onScroll(progress)`,
`onSlidesInView(indexes)`, `onReInit(snapCount)`, `onAutoplayChange(playing)`,
`onAutoScrollChange(playing)`, `onSlideFocus(index)`.

## Responsive
Mobile first: one slide per view unless `slidesToShow` says otherwise per breakpoint; controls wrap;
floating arrows sit inside the slides' edges; touch swipes are native.

## Parity notes
The HTML runtime adds or removes dots when the measured number of snaps differs from the markup
(React re-renders them). Parity ignores `style` (sizes and controller values).
