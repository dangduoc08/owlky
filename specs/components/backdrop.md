# Backdrop

Reference: MUI "Backdrop" demo page, sections Example, Transitions (content only; Minimals has no
Backdrop page). Upstream: MUI `Backdrop` (ADR-0015). Created with `/component`.
Reference URL: https://mui.com/material-ui/react-backdrop/

## Purpose
A dimmed layer over the whole viewport that shows content (usually a loader) in front of the page.
Display is CSS only; the HTML runtime `backdrop` adds triggers and events. No core controller:
React renders from `open`.

## Anatomy
```
button[data-ok-backdrop-open="id"]                       (HTML trigger)
div[data-ok-backdrop][id][data-ok-open]?[data-ok-invisible]?[data-ok-backdrop-close]?
  › children (e.g. span[data-ok-circular-progress][data-ok-color="inherit"][aria-label])
```

## Options

Root: `data-ok-backdrop`. Unknown values fall back to the default.

| React | HTML | Kind | Values | Default | Description |
|---|---|---|---|---|---|
| `invisible` | `data-ok-invisible` | flag | boolean | off | Transparent: blocks clicks without dimming the page (for example, behind a custom menu). |
| `transitionDuration` | `data-ok-transition-duration="…"` | number | number | — | Length of the fade in and out (ms). Default: the theme's durations. |
| `open` | `data-ok-open` · event `ok:backdrop:close` | state | — | — | Open state (`open`; HTML: `data-ok-open`, a trigger or `open()`). |
<!-- /options:backdrop -->

React: `open` (required, `data-ok-open` when true), `invisible`, `children`, `ref` and DOM props
on the root (`onClick` closes it in the demo). Deferred: `transitionDuration` (upstream API audit,
`docs/roadmap.md`). Not applicable: `component`, `slots`, `slotProps` (one `div`), `classes`,
`sx`, Fade props (`TransitionComponent`: one CSS fade).

## Layout and tokens
`position: fixed; inset: 0`, flex centered, `z-index: var(--ok-z-modal)` (upstream is `-1` inside
Modal; the reference demo raises it above the drawer). Background `--ok-backdrop`
(`data-ok-invisible`: transparent), text `--ok-palette-common-white`, `-webkit-tap-highlight-color:
transparent`. Closed: `opacity: 0; visibility: hidden` (out of the accessibility tree, no hit
testing). Fade: opacity in `--ok-duration-short`, out `--ok-duration-shorter`,
`--ok-easing-standard` (upstream 225 / 195 ms); none with `prefers-reduced-motion`.

Contrast: white over `--ok-backdrop` on a white page is 2.97:1 in light mode (dark: 17.5:1;
upstream black 50%: 3.98:1). Accepted (one backdrop look with Dialog and Drawer); text goes on a
paper inside the backdrop, not on the backdrop itself.

## Responsive behavior
Covers the viewport at every width; children stay centered. No breakpoint changes.

## Keyboard / Accessibility
Not focusable, no role, no key handling (upstream): focus stays where it was (the trigger) and the
page behind stays reachable by keyboard. The children carry the semantics (a progress has
`role="progressbar"` and a name). For a blocking surface that keyboard users can dismiss, use
Dialog. Close a loading backdrop when the work ends.

## Events / API
HTML triggers: `[data-ok-backdrop-open="id"]`; `[data-ok-backdrop-close="id"]`, or
`[data-ok-backdrop-close]` with no value inside a backdrop or on the backdrop itself (a click
anywhere on it closes it, like the reference's `onClick`). `data-ok-open` opens it on load.
Events: `ok:backdrop:beforeopen` (cancelable, `detail.trigger`), `ok:backdrop:open`,
`ok:backdrop:beforeclose` (cancelable, `detail.reason`: trigger | api), `ok:backdrop:close`.
Instance: `{ isOpen, open(trigger?), close(reason?) }`.

## Upstream API mapping
Audit 2026-11-09 against MUI API page Backdrop (inherits Fade).

| Upstream | Owlky | Status | Note |
|---|---|---|---|
| `open`, `invisible`, `children` | same; HTML `data-ok-open`, `data-ok-invisible` | kept | |
| `transitionDuration` | same, a number of ms for both fades; HTML `data-ok-transition-duration` | kept (4.9) | core `backdropStyle` → `--_ok-backdrop-duration` (React `style`, HTML CSSOM); `{ enter, exit }` not applicable |
| `component` | — | not applicable | one `div` |
| Fade props (`appear`, `easing`, `timeout`, `addEndListener`, `onEnter`… callbacks) | one CSS fade | not applicable | HTML `ok:backdrop:open` / `close` events |
| `sx`, `classes`, `slots` / `slotProps`, `components` / `componentsProps`, `TransitionComponent` / `TransitionProps` | — | not applicable | ADR-0015: CSS, composition, one CSS transition |

## Parity notes
None: both render the same `div`; React adds `data-ok-runtime="off"`.

## Relation to Dialog and Drawer
Their exits (ADR-0062) run in the core modal controller, which Backdrop doesn't use: its own fade
out is already a CSS transition in both directions, so Backdrop is unchanged by 5.1.

Their modal paths keep the native `::backdrop` (top layer: a DOM element can't sit between a
top-layer `<dialog>` and its `::backdrop`), painted with the same `--ok-backdrop`; their
`hideBackdrop` matches `invisible`.
