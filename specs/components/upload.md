# Upload

Reference: Minimal UI kit "Upload" page (sections Upload single file, Upload multi file — with the
"Horizontal layout" and "Show image" switches, the file list, Remove all and Upload buttons —,
Upload avatar and Upload box; content only). Upstream: react-dropzone (`useDropzone` options,
state and `open()` / `removeFile()` / `clearFiles()`), as a behavior and API reference
(ADR-0015, ADR-0037). Created with `/component`.
Reference URL: https://minimals.cc/components/extra/upload

The upstream is React only (no HTML version): the HTML side is written by us.

## Purpose
Let people choose files by dropping them on a zone, pressing it (file dialog), pressing Enter or
Space, or pasting; check each file (type, size, count, a custom validator); keep the accepted
files (single: replace; multiple: add), show them (preview in the zone, or a list of rows / tiles
with thumbnails, names and sizes) and list the rejected ones with their reasons. No network: the
owner sends the files. The files are mirrored into the native input (`DataTransfer`), so a form
submits them.

## Anatomy

Any `[data-ok-upload-open]` inside the root opens the dialog (both implementations).
`data-ok-kind`: image · video · audio · pdf · document · spreadsheet · presentation · archive ·
text · code · other (from the extension, then the MIME type).

## States
- Drag: `data-ok-drag` while files are over the zone — `accept` (primary border), `reject`
  (error colors: too many files, or a known MIME type outside `accept`), `unknown` (decided at
  drop: extensions, a validator); `data-ok-drag-global` while files are dragged over the page.
- Busy: `aria-busy="true"` while files are read or an async validator runs.
- Error: `data-ok-error` (zone and helper text in error colors, input `aria-invalid`).
- Disabled: the input's `disabled` (zone at 0.48 opacity, no drops, no dialog).
- Focus: the input's `:focus-visible` draws the zone's outline.
- Hover (pointer devices) and drags: a grey 500 border (the reference dims the zone to 0.72,
  which takes the description below AA).

## Behavior
- Core `createUploadController` (both implementations): drag enter / over / leave / drop on the
  root (target counting, verdict, `dropEffect`), drops always prevented inside the root; folders
  read recursively (`webkitGetAsEntry`); paste of files (`noPaste`); Enter on the input and
  `[data-ok-upload-open]` → `open()`; `noClick` (CSS `pointer-events: none` on the input + JS
  refusal of pointer clicks); `useFsAccessApi` → `showOpenFilePicker` (AbortError → cancel,
  NotAllowed / SecurityError → the input); `cancel` event / empty `change` → dialog cancel (the
  held files go back into the input); form `reset` → cleared; `preventDropOnDocument` (document
  `dragover` / `drop` outside uploads prevented); `noDragEventsBubbling` (inner upload claims
  the event, outer ones skip it; no `stopPropagation`). The latest drop wins over pending async
  checks.
- Checks (core `evaluateUploadFiles`): type, `maxSize`, `minSize`, validator errors per file; then
  `too-many-files` past the limit (single: 1; multiple: `maxFiles` minus the files held).
- Owners: single → a new accepted file replaces the old one; multiple → added. Rejections show the
  latest drop's. Object URLs for image previews are revoked when the file leaves and on unmount /
  destroy. After removing with a focused button, the focus moves to the next remove button, else
  the input.
- HTML runtime `upload`: renders the preview, the list (template clones, kept per file), the
  rejections, the avatar title and the actions' `hidden`; `noKeyboard` → `tabindex=-1`.

## Keyboard
| Key | Action |
|---|---|
| Tab | The input (zone), then remove and action buttons |
| Enter / Space | Opens the file dialog (not with `noKeyboard`) |
| Ctrl/Cmd + V | Pastes files (not with `noPaste`) |
| Enter / Space on a remove button | Removes the file; focus moves on |

## Accessibility
The native file input is the control (named by the title or `aria-label`, described by the
helper text). Rejections are an alert; the list is a polite live region. Remove buttons are named
"Remove <file name>". Text: description and helper text in `text-secondary`, "browse" in the
primary AA text tone, error texts in the error AA tone. File names are always text
(`textContent` / React children). A disabled zone is dimmed (inactive component, exempt from
contrast in tests).

## Events / API
HTML events (on the root): `ok:upload:drop` (cancelable, `{ accepted, rejections }`),
`ok:upload:change` (`{ files, reason }`), `ok:upload:remove` (cancelable, `{ file }`),
`ok:upload:upload` (`{ files }`), `ok:upload:dialogopen`, `ok:upload:dialogcancel`,
`ok:upload:drag` (`{ active, verdict, global, rejections }`), `ok:upload:error` (`{ error }`).
Instance: `files`, `rejections`, `dragState`, `isFileDialogActive`, `isProcessing`, `open()`,
`setFiles()`, `removeFile()`, `clearFiles()`, `setValidator()`, `setErrorMessage()`,
`setFilesFromEvent()`.
React also exports `useDropzone(options)` and `Dropzone` (react-dropzone's hook and render prop, see the mapping).

## Responsive
The zone, list and actions fill their container at every width; names are cut with an ellipsis;
tiles wrap; the description wraps; actions wrap and stay at the end. No breakpoint changes.

## Parity notes
- The HTML list item comes from `<template data-ok-upload-template>` (skipped by parity).
- Ids differ (React `useId`, HTML from the input's id or `createId`); parity normalizes them.
- Image previews are object URLs (different per page): dynamic parity runs with `thumbnail` off.
