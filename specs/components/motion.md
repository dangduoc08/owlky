# Motion

Reference: Minimal UI kit "Animate" page, tabs In View, Scroll, Dialog, Background and Other
(Tap & hover, Path, Count up, Logo, Avatar, Border) (content only); Countdown from the "Utilities"
page, section Countdown (https://minimals.cc/components/extra/utilities, roadmap 4.22). Upstream: Framer Motion
variants (`initial` / `animate` / `exit`, `whileInView`, `viewport.once` / `amount`,
`staggerChildren`, `whileHover` / `whileTap`) — mapped to CSS animations, no dependency
(ADR-0015). Created with `/component`; named Motion because `data-ok-animate` is the
IconButton / Fab hover flag. Full version (roadmap Phase 5, ADR-0062): 5.1 engine (`animate()`,
springs, interruption, custom keyframes, exits before removal), 5.2 scroll (scroll-linked
Linear / Circular progress, `useScroll`: `specs/components/scroll-progress.md`), 5.3
gestures (drag with inertia and constraints, spring hover / tap / focus / drag states, a shared
swipe helper) and 5.4 layout (FLIP layout animations, `layoutId`, `LayoutGroup`, shared values)
done; 5.5 shared-element transitions stays deferred (ADR-0062, note of 2026-11-11).
Reference URL: https://minimals.cc/components/extra/animate

## Purpose
Entrance and exit animations for any content (Motion), staggered groups (MotionGroup), letter by
letter text (MotionText), looping backgrounds (Ken Burns, pan, color change), SVG stroke drawing,
hover / press scaling, counters (CountUp), countdowns to a date or for a number of seconds
(Countdown) and turning gradient borders (MotionBorder). The CSS plays
the animations; core decides when (`createMotionTrigger`: mount, in view, manual) and counts
(`createCountUp`). Without JavaScript nothing is hidden: the start state needs `data-ok-state`.
Custom keyframes (`keyframes` / `data-ok-keyframes`) and core `animate()` play with the Web
Animations API instead (ADR-0062).

Custom keyframes (ADR-0062; free JSON, so not in the schema, like `viewportMargin`): React
`keyframes` (Framer's `animate` object: a value or a list per property, `null` = the current value;
`x` / `y` → `translate` px, `scale` / `scaleX` / `scaleY` → `scale`, `rotate` → `rotate` deg, other
CSS properties as they are) and `transition` (Framer's `transition` in ms: `duration`, `delay`,
`ease` (CSS easing, token name `standard` · `decelerate` · `accelerate` · `expressive`, Framer
names, control points, or one per segment), `times`, `repeat` (`Infinity`), `repeatType`
(`loop` · `reverse` · `mirror`), `repeatDelay`, `type: "spring"` with `stiffness`, `damping`,
`mass`, `velocity`, `bounce` + `duration` / `visualDuration`, `reducedMotion`). HTML
`data-ok-keyframes` / `data-ok-transition` (JSON, `"repeat": "Infinity"`); React writes the same
attributes (`motionKeyframesAttributes`). Values are filtered (property names, no `url(`, `;`,
braces; at most 64 frames, 200 characters).

Gestures (5.3; free values, so not in the schema, like the keyframes): React props on `Motion`
(Framer's names) and the same attributes in HTML (`motionGestureAttributes`): `drag` (`true` →
`data-ok-drag`, `"x"` / `"y"` → its value), `dragConstraints` (a box in px from where the element
sits → JSON; an element's `id` → the id; a ref → React only, no attribute), `dragElastic` (0–1,
`true` = 0.5, `false` = 0, or a box per side; default 0.5), `dragMomentum` (default `true`;
`false` → `"false"`), `dragSnapToOrigin`, `dragDirectionLock`, `dragTransition` (inertia: `power`
0.8, `timeConstant` 750 ms, `bounceStiffness` 200, `bounceDamping` 40, `restDelta` 1,
`restSpeed` 10; `modifyTarget(target, axis)` React only), `whileHover`, `whileTap`, `whileFocus`,
`whileDrag` (keyframes like `keyframes`, plus an optional `transition` key; filtered the same way).
The element's `transition` is written as `data-ok-transition` with any gesture and applies to
states without their own. Callbacks (React, Framer's order `(event, info)`): `onDragStart`,
`onDrag`, `onDragEnd` (`info`: `point` on the page, `delta`, `offset`, `velocity` px/s; `event`
`null` when the browser cancelled the pointer), `onDirectionLock(axis)`, `onDragTransitionEnd()`,
`onHoverStart(event)`, `onHoverEnd(event)`, `onTapStart(event, { point })`, `onTap`, `onTapCancel`.

MotionPresence (React; Framer `AnimatePresence`): `children` with keys, `initial` (default
`true`; `false` skips the first entrance of the children rendered with it), `mode` (`sync` ·
`wait` · `popLayout`, 5.4), `onExitComplete`. `popLayout`: in the commit that removes a child,
its top Motions (registered ones not inside another) leave the flow: `position: absolute` with
their offset box (`offsetTop` / `offsetLeft` minus the margins, `offsetWidth` / `offsetHeight`,
`box-sizing: border-box`, CSSOM), so siblings with `layout` are measured after it (core flush,
a microtask later) and move into its place while it exits; the inline styles are restored when
the child comes back. Like Framer's `PopChild`: the Motion must be the child's root, inside a
positioned parent. HTML has no presence component: `remove()` removes the element after its exit,
and siblings with `data-ok-layout` move then. Context to the Motions inside a child: a
removed child renders `data-ok-state="exit"` on its Motion, MotionGroup and MotionText roots and is
unmounted when their animations end (core `waitForAnimations`, late look for keyframes).

Layout (5.4; free values, so not in the schema, like the gestures): React props on `Motion`
(Framer's names) and the same attributes in HTML (`motionLayoutAttributes` / `readMotionLayout`):
`layout` (`true` → `data-ok-layout`, `"position"` / `"size"` → its value; any other value in HTML
reads as `true`), `layoutId` (`data-ok-layout-id`; implies `layout`), `layoutDependency` (React
only: measures when the value changes, `Object.is`; HTML has no re-render, see `measure()`),
`onLayoutAnimationStart()` / `onLayoutAnimationComplete()` (HTML `ok:motion:layoutanimationstart`
/ `layoutanimationcomplete`). `transition` (`data-ok-transition`) is written with layout too; its
`layout` key (Framer's `transition.layout`, one level, parsed like the rest) wins for layout
animations, else the transition minus `repeat`, `repeatDelay` and `times`. React `LayoutGroup`
(`id`, `inherit`: `true` joins the enclosing group's members and prefixes its id, `"id"` only
the id, `false` neither; no element); HTML `data-ok-layout-group="<id>"` on a container.
`initial` is a schema option (above): `false` skips the entrance (no `data-ok-state` until the
first exit or `replay()`), for elements that move instead of entering (`layoutId`).

Shared values (5.4): core `motionValue(initial)` → `SharedValue<T>` (`get`, `set`, `jump`,
`getVelocity`, `on("change")`, `stop`, `destroy`; renamed from Framer's `MotionValue`, which names
a keyframe value in Owlky), `transformValue(value, fn)` / `([values], fn)` / `(value, input,

HTML: the same core functions from `@owlky/html` in a page script; no attributes (a declarative
form would need an expression language for the functions, and every use already needs a
script to set the values).

## Layout and tokens
Entrances: `--ok-duration-enter` (640ms), exits `--ok-duration-exit` (480ms),
`--ok-easing-expressive`. Distances: 160px (`--ok-spacing` × 40) slides, 120px fades, 360px
directional zoom / bounce. Loops: `--ok-duration-enter` × 8 (≈ 5 s). Draw: × 3. Interactive:
scale 1.09 on hover, 0.97 pressed, `--ok-duration-shorter`. Color change: a gradient of primary,
warning, secondary and error `main`, 2–5 times the text width (the element shrinks to its content).
Countdown: inline-flex row, gap 24px (`--ok-spacing` × 6); each unit a centered column, value
`--ok-typography-h5-*` with tabular figures, label `--ok-typography-body2-*` in
`--ok-text-secondary`. Values below the largest unit have two digits (`05`).
MotionBorder: 2px, `--ok-radius-lg` (circle: 50%), three layers: the fill on the padding box
(`--ok-bg-paper`, `--_ok-motion-border-fill`), a conic gradient on the border box (multi: the same
four colors all around; `inherit` / a palette color: a light about 90° long, symmetric; with
`secondaryColor`: a second light 180° away) and a faint track under it (135°, first light's channel
at 8% → second light's at 24%; `inherit` and `multi` use `--ok-palette-grey-500-channel`). CountUp: tabular figures, ease-out cubic, 2000ms.

## Behavior
`initial` holds in-variants at their start (paused animation) and out-variants as themselves;
`enter` plays; `exit` plays the other way (other keyframe name, so it restarts). An entered
in-variant drops the animation at its end (`animation-fill-mode: backwards`): no transform is left.
`inView` (IntersectionObserver; none → shown at once): plays when `amount` is visible; `once=false`
exits when it leaves. `viewportMargin` is the observer's `rootMargin` (invalid → none),
`viewportRoot` its `root` (HTML: the element with that id; unknown → the browser viewport). Both
are read when the trigger starts. Viewport events: enter once per crossing into view (the
`amount` visible), leave when nothing is visible after an entrance; with `once`, the first
entrance only. Only the element that owns the trigger reports (a Motion in a group doesn't);
`mount` and `manual` triggers don't observe, so they report nothing. `mount`: at once. `manual`: follows `in` / `data-ok-in`. Changing `variant`,
`duration` or `distance` replays an entered Motion (React too). MotionGroup drives every Motion
whose closest group it is. Loops run while entered, `paused` stops them. Reduced motion: entrances
and exits take 1ms, loops and the border don't run, interactive doesn't transition, CountUp shows
the end at once.

Custom keyframes (core `createMotionKeyframes`, both owners): the player watches `data-ok-state`;
`enter` plays the keyframes with `animate()`, `exit` plays them backwards (single targets go back
to the value before the first entrance; repeats dropped), `data-ok-paused` pauses them, a change of
the JSON replays, removing it cancels. The CSS variant is off while `data-ok-keyframes` is present
(`animation: none`). Without a state (no JavaScript) the element shows its own style. Reduced
motion (also when it changes while running): non-looping keyframes jump to the end, loops don't
run.

Engine (`animate()`, ADR-0062): one Web Animation per CSS property, easing per segment (Framer),
`fill: both`, end values committed to the inline style (`commitStyles()`) and the animation
cancelled, loops never committed; an interrupted property starts from its computed value; springs
sampled into `linear()` (rest: within 0.001 and slower than 0.01/s, at most 10 s), fallback where
`linear()` isn't supported: `cubic-bezier(0.34, 1.56, 0.64, 1)` for bouncy springs,
`--ok-easing-decelerate` otherwise. Default duration `--ok-duration-standard`, easing
`--ok-easing-standard` (read from the document's computed style). Controls: `finished` (never
rejects), `cancel`, `stop`, `complete`, `pause`, `play`, `animations`.

Exit before removal (core `playExit` / `waitForAnimations`): writes `data-ok-state="exit"` (Motion
roots) or `"exiting"` (other elements), flushes style, waits for the finite animations of the
subtree (a microtask later again when keyframes are inside), with a safety timer (longest
remaining + 100 ms). `cancel()` restores the previous state. HTML instance `exit()` / `hide()` /
`remove()` resolve `false` when `replay()` interrupts them.

Gestures (core `createMotionGestures`, both owners; `drag.ts`, `gesture.ts`, ADR-0062 5.3):
- **Drag** (`createDrag` on `trackPan`): a primary pointer press, then 3 px of movement start a
  drag (pointer captured where allowed); the element follows through its `translate` (CSSOM),
  from where it was (a running glide stops where it is when pressed). Axis lock keeps the other
  axis; the direction lock waits for 10 px on one axis (vertical first, Framer). Constraints are
  read when a drag starts: a box, or an element whose box it stays in (its layout box without
  transforms; larger than the element → it may move while it covers it). Past a constraint it
  moves by `dragElastic` (0 stops at it). On release: with momentum, an inertia glide from the
  release velocity (last 100 ms) towards `from + power × velocity`, with a spring back once it
  crosses a constraint (`dragElastic` 0 on both sides of an axis: a hard stop); without momentum,
  only the spring back from an elastic overdrag; `dragSnapToOrigin`: a spring back to no
  translate. The glide is simulated per axis (1 ms steps, rest under `restDelta` / `restSpeed`,
  at most 10 s) and played by `animate()` as `translate` keyframes every 1/60 s (linear), so the
  end is committed inline. `pointercancel` ends a drag like a release without velocity. A press
  inside a nested draggable drags only the innermost one. Native image / link drag is prevented
  while draggable. CSS: `cursor: grab` (`grabbing` while `data-ok-dragging`), no text selection,
  `touch-action: none` (`pan-y` for `x`, `pan-x` for `y`, so the page scrolls along the free axis).
- **Keyboard alternative** (Owlky addition, WCAG 2.1.1 / 2.5.7): while the draggable element
  itself has the focus, arrow keys move it 10 px (50 px with Shift) along its axes, clamped to its
  constraints, and report a drag start, a move and an end (velocity 0). Make it focusable
  (`tabindex="0"`) and give it a name (`role="group"` + `aria-label`) and a visible hint.
- **States**: hover (`pointerenter` / `pointerleave`, mouse and pen only), tap (a primary pointer
  press until its release: on the element → `tap`, outside → `tapcancel`; `pointercancel` and a
  drag that starts → `tapcancel`; Enter or Space on the focused element or a `button`, `a[href]`,
  `[role="button"]` or `summary` inside it, until the key's release; losing the focus cancels),
  focus (`focusin` whose target matches `:focus-visible`, until the focus leaves the element),
  drag (while dragging). Order (lowest first): focus, hover, tap, drag; each property follows the
  highest active state that names it. A property's own value (computed, and its inline value) is
  kept when a state first takes it; when no state names it any more it animates back and its
  inline value is restored (none → removed). Unchanged targets don't replay. Transitions: the
  state's own, else the element's `transition`, else Framer's defaults (springs: `translate`,
  `rotate` stiffness 500 damping 25, `scale` 550 / 30; anything else a 300 ms tween,
  `[0.25, 0.1, 0.35, 1]`).
- **Reduced motion** (`prefers-reduced-motion: reduce`): the element still follows the pointer
  and the arrow keys; a release settles at once (clamped to the constraints, or at the origin):
  no glide, no spring; states jump to their values (the engine's rule).

Swipe (core `createSwipe` on `trackPan`, shared helper): the first 3 px pick the axis; an axis
without an allowed direction (`top` · `right` · `bottom` · `left`) lets the press go; moves report
`distance` towards the direction (moving back is negative with one allowed direction) and
`speed`; the release is a swipe at `threshold` px (default 50) or `velocity` px/s (default 450)
towards an allowed direction, otherwise a cancel. Used by the swipeable Drawer. The Snackbar's
toast swipe (`createToastSwipe`) stays as it is: it measures the average speed of the whole swipe
and resists moves in other directions; moving it onto the helper would change when a toast
dismisses (no behavior change in 5.3).

Countdown (core `createCountdown`, both owners): the time left is `date − clock` (date mode) or
`seconds` minus the running time (seconds mode), shown in whole seconds rounded up (10 → 0) and
split from `largestUnit` down (a larger unit folds into it: 90 seconds with `minutes` = `1` minute
`30` seconds). The clock is `now + (Date.now() − mount time)` when `now` is given, otherwise
`Date.now()`. Without `now` a date countdown renders `--` for every value until it mounts (no
server / client mismatch); a seconds countdown renders its full time. A timer fires when the shown
value changes (aligned to the next whole second, not every frame). At 0 it stops, reports
`complete` once and announces `completeLabel`; a date in the past completes at mount. `paused`:
a seconds countdown keeps its time left; a date countdown freezes its text and shows the real time
left when it resumes (the date doesn't move). Changing `date` / `seconds` starts over.
Live region cadence (`[data-ok-countdown-status]`, polite): nothing at mount, then the time left
(non-zero units, such as "2 hours, 15 minutes") each time it crosses a whole hour while at least
an hour is left, each whole minute while at least a minute is left, at 30 and 10 seconds, and
`completeLabel` at the end. Announcing every second would flood screen readers and stop them from
reading anything else; the visible text stays readable at any time (the root's `timer` role is
not live). Triggers: `data-ok-countdown-toggle` flips `data-ok-paused` and mirrors it in its
`aria-pressed`; `data-ok-countdown-restart` starts over and runs.

Layout (core `createLayoutNode`, `flushLayout`, `layout.ts`, ADR-0062 5.4):
- **Boxes** are layout boxes in page coordinates: the bounding box when neither the element nor
  an ancestor has a computed `transform`, `translate`, `scale` or `rotate`; otherwise the offsets
  (`offsetLeft` / `offsetTop` up the offset parents, minus the scroll of scrolling ancestors;
  whole pixels). So CSS entrances, drags, ancestors' layout animations and its own running
  animation never count as layout, and nothing is cancelled to measure.
- **Snapshot → flush**: an owner snapshots before a change (`live`: measured now; `last`: the
  last box measured); a flush (a microtask later, or `flushLayout()`) reads every box first
  (layout boxes, `transform-origin`, corner radii), then starts the animations. A node that is
  animating snapshots where its path shows it (the path's time is its animation's
  `currentTime`), so an interruption starts there. Changed boxes (half a pixel) get a path
  `from` (mode applied: `position` keeps the new size, `size` the new position) `to` the new box.
- **Playback**: `animate()` on `transform` (never committed: `commit: false`), around the
  element's computed `transform-origin`: two keyframes (the inverse transform → `none`) with the
  transition's easing (springs as `linear()`), or sampled every 1/60 s with linear easing when the
  node needs a correction. Default timing: the engine's (`--ok-duration-standard`,
  `--ok-easing-standard`; Framer's 450 ms curve is not copied). A path whose target didn't change
  keeps running untouched.
- **Size correction (how far it goes)**: (1) a node inside a node that animates gets its own path
  in page coordinates and its transform is that path in the parent's frame (the parent's current
  scale and translate undone, frames sampled on each path's own clock), so a nested Motion with
  `layout` keeps its size and moves on its own; a nested node that nobody snapshotted moved with
  its parent (rigid) and needs no animation when the parent only moves; (2) corner radii in px
  are drawn divided by the visible scale (elliptical `rx ry` per corner, sampled). Not done:
  plain children (text, images) scale with their box, as in Framer (wrap them in a Motion with
  `layout="position"`); percent radii (they follow the box anyway); `box-shadow` correction;
  rotated or skewed elements (scale and translate only); an author `transform` on the element is
  replaced while a layout animation plays (use `translate` / `scale` / `rotate`); `display:
  inline` elements (transforms don't apply).
- **layoutId**: a node created with a `layoutId` (scoped by its group's id) takes the box a node
  with the same id left when it was destroyed in the same frame (React unmounts it on the page;
  HTML after removal: its last box), or the box of one that is still there, and animates from it.
  No crossfade between both (5.5 shared-element transitions).
- **Groups**: a snapshot of a group member snapshots every other member without
  `layoutDependency` (Framer's LayoutGroup re-renders them; here core measures them directly).
- **Focus**: elements are never moved or re-inserted. A focused element inside a snapshotted node
  (React: before the commit; HTML: the last `focusin` target, when a mutation removed it or an
  ancestor) that the change blurred to the page gets the focus back (`preventScroll`); a focus
  the user moved elsewhere is left alone.
- **Events**: start when a node's own box changed and its animation started; complete when it
  finished (not when interrupted or cancelled); a correction-only animation reports nothing.
- **Reduced motion** (the transition's `reducedMotion`, default `user`): no animation, the boxes
  jump; start and complete are still reported for changed nodes.
- **React**: a class component in Motion takes the snapshot in `getSnapshotBeforeUpdate` (before
  React changes the DOM, each render; with `layoutDependency` only when it changed); the node is
  created and destroyed in layout effects.
- **HTML runtime** (`components/motion/layout.ts`): one MutationObserver on the document (module
  scope) while a layout Motion exists. The DOM already changed when it reports, so affected nodes
  (a mutation inside their parent element, or inside their `[data-ok-layout-group]`) snapshot
  their last box and flush at once; every other idle node only measures again, as after a resize
  (ResizeObserver on the nodes and their parents) or a scroll (capture listener). Moves keep the
  instance (the runtime checks connectedness), so moving an element animates it from its old
  place. Instance `measure()` (a live snapshot) and `animateLayout()` (snapshot from the last box,
  flush now) cover changes no mutation shows (a stylesheet's rules, a media query).

## Keyboard
Not interactive, except gestures. Layout animations keep the focus where it is (above). A draggable Motion with the focus: arrow keys move it (10 px,
Shift: 50 px). With `whileTap`: Enter and Space press it (on the Motion or a button inside it).
Content inside keeps its own keyboard behavior.

## Accessibility
Content never depends on the animation (no JavaScript → shown; reduced motion → shown at once).
MotionText and CountUp hide the moving copy (`aria-hidden`) and expose a visually hidden label with
the whole text / end value. Countdown: `role="timer"` (not live; name it with `aria-label`), a
polite status region on the cadence above, a pause control for anything that runs more than 5
seconds next to other content (WCAG 2.2.2: `data-ok-countdown-toggle` or React `paused`). Loops need a pause control (WCAG 2.2.2): `paused`. Directional
entrances start outside the box: clip containers that could widen the page. Gestures: dragging is
a pointer gesture, so anything a drag does needs another way (WCAG 2.5.7 Dragging Movements,
2.1.1): the arrow keys on a focusable draggable, or buttons; hover-only states never carry
information; a tap state also answers Enter and Space. Owlky never adds a `tabindex` (Framer
does for tap elements): put `whileTap` on a focusable element or around a button.

## Parity notes
React renders `data-ok-runtime="off"` and writes `data-ok-state` itself (SSR: `initial`); snippets
carry no state (the runtime writes it). React 19's `<link rel="preload">` hints next to images are
skipped by parity. Private properties go through `style` (ignored by parity). The Countdown story
passes `now`; parity and the e2e tests fix `Date.now()` (`page.clock.setFixedTime`) so both
renderings show the same time.
