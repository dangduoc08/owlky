# Paper

Reference: MUI "Paper" demo page, sections Introduction (basic), Elevation, Variants, Corners
(content only; Minimals has no Paper page — its theme customizes MUI's Paper: no dark-mode
overlay, a grey 500 / 16 % outline). Upstream: MUI `Paper` (ADR-0015). Created with `/component`.
Reference URL: https://mui.com/material-ui/react-paper/
HTML source: written by us (MUI is React only)

## Purpose
A surface: the paper background, the primary text color, rounded corners and an elevation
shadow (or a 1px outline). CSS only; the base other surfaces (Card) are built on.

## Anatomy
```
<element>[data-ok-paper][data-ok-variant][data-ok-elevation][data-ok-square]?   any content
```
The element is the author's: `div` by default (React `component`, HTML any element such as
`section`, `article`, `li`). Paper adds no role: it is a visual surface only.

## Layout and tokens
`--ok-bg-paper` background, `--ok-text-primary` text, `--ok-radius-md` corners (`square`: 0).
`elevation` 0–24 → `box-shadow: var(--ok-elevation-<n>)` (0: none), changes animate over
`--ok-duration-standard` / `--ok-easing-standard` (none with reduced motion). `outlined`: no
shadow, `1px solid rgb(var(--ok-palette-grey-500-channel) / 0.16)` (Minimals' theme), elevation
ignored. No size, padding or display of its own: the content and the author's layout decide.
Dark mode: the same `--ok-bg-paper` at every elevation (Minimals' theme drops MUI's lightening
gradient; the dark paper already differs from the dark page background).
Glass paper (Minimals "Utilities › Gradient › Paper", row 4.21): no option; the
`--ok-gradient-paper` token as `background` plus a `backdrop-filter` on any Paper (Foundations ›
Colors › Gradient), so the schema stays MUI's.

## Composition contract (Card and other surfaces)
- **Card** (`specs/components/card.md`, next) is a Paper root: its element carries
  `paperAttributes()` *and* `data-ok-card` (React: `<Paper {...props} data-ok-card="">` or the
  same attributes on its own element; HTML: `data-ok-paper … data-ok-card` on one element). It
  reuses Paper's `variant`, `elevation` and `square` options (spread `paperOptions.options` into
  its schema) and adds its own.
- `paper.css` is imported **first** among the components in `styles/src/index.css`: every rule is
  a zero-specificity `:where()`, so a composing component's CSS (loaded later) overrides Paper's
  radius, shadow or background by source order — e.g. `:where([data-ok-card]) { border-radius:
  var(--ok-radius-2xl); box-shadow: var(--ok-shadow-card) }`. Such a component restates what must
  still win over its own rule: `:where([data-ok-card][data-ok-variant="outlined"])` (no shadow),
  `:where([data-ok-card][data-ok-square])` (no radius).
- Paper sets only `background-color`, `color`, `border-radius`, `box-shadow`, the border
  longhands (the style's surface edge: `--ok-surface-border-width|style|color`; `style` may name
  each side, Editorial's `solid none none` top rule, ST7) and `transition`. Floating Papers
  (`[data-ok-dialog-paper]`, `[data-ok-drawer-content]`, popover roots, map controls and popups)
  restate `border-style: solid`, so a one-sided style keeps their whole edge (ST7b: popovers keep
  Paper's edge, so flat styles still outline menus and lists): no `display`, `overflow`, padding or size, so a composer adds them
  without undoing anything. No private variables (they would inherit into nested papers).
- Library surfaces composed on Paper (ADR-0066, 2026-11-12): every popover root (Popover, Menu,
  Select, Autocomplete, pickers, Walktour steps, Editor overlays), the Dialog paper, the Drawer
  content, Map controls and popup contents carry `data-ok-paper` on their own element, right
  after their marker, and keep their look by restating radius, background and shadow after
  `paper.css`. Popover, Menu and Dialog take `elevation` (`data-ok-elevation`, written only when
  given; their default shadow rule is `:not([data-ok-elevation])`); Drawer keeps its own
  `elevation`. `TableContainer component={Paper}` (HTML: Paper's attributes on the container)
  puts a table on a surface. Core `surfacePaperAttributes(elevation)` writes the marker.

Stories: the labels are Typography `body2` (`textSecondary` on the Elevation levels, as in the
reference); `sb-paper-*` classes give sizes and centering only.

## Responsive behavior
Fluid: no width or height of its own; nothing changes per breakpoint.

## Keyboard / Accessibility
Not focusable, no role. Content on paper uses `--ok-text-primary` / `--ok-text-secondary`
(AA on `--ok-bg-paper` in both schemes). The shadow and outline are decorative: don't convey
meaning by elevation alone.
